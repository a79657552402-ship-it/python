Теория — Основные вопросы
1. Python - какой это язык? Кто создал? Когда появился? Различия версий?
Python — это высокоуровневый язык программирования общего назначения с динамической строгой типизацией и автоматическим управлением памятью. Его синтаксис приближен к естественному языку, что делает код легко читаемым и понятным. Python интерпретируемый, кроссплатформенный и поддерживает несколько парадигм программирования: объектно-ориентированное, процедурное, функциональное и асинхронное.
Кто и когда создал
Создателем Python является нидерландский программист Гвидо ван Россум. Работа над языком началась в декабре 1989 года в центре математики и информатики (CWI) в Нидерландах. Изначально это был любительский проект: Гвидо искал занятие на время рождественских каникул.
Первая публичная версия — Python 0.9.0 — была выпущена 20 февраля 1991 года. Уже тогда в язык входили классы с наследованием, обработка исключений, функции и основные типы данных (list, dict, str).
Название языка не связано с змеями. Гвидо ван Россум был поклонником британского комедийного шоу «Летающий цирк Монти Пайтона» (Monty Python's Flying Circus), поэтому и выбрал такое имя.
Основные версии и их отличия
Развитие языка прошло через несколько ключевых этапов:
Версия	Год	Ключевые особенности
Python 0.9.0	1991	Первая публичная версия с базовыми возможностями: классы, функции, обработка исключений.
Python 1.0	Январь 1994	Добавлены функциональные инструменты: lambda, map(), filter(), reduce().
Python 2.0	Октябрь 2000	Внедрены списковые включения, улучшенная сборка мусора, поддержка Unicode.
Python 3.0	Декабрь 2008	Фундаментальное обновление, которое нарушило обратную совместимость с Python 2.x. Цель — устранить недостатки в архитектуре языка и проблемы безопасности.
Ключевые различия между Python 2 и 3:
	Print : В Python 2 это оператор, в Python 3 — функция.
	Input : В Python 2 есть функция raw_input(), в Python 3 введена единая функция input(), которая всегда возвращает строку.
	Unicode по умолчанию: В Python 2 строки по умолчанию хранятся в кодировке ASCII, в Python 3 используется Unicode.
	Аннотации типов: Python 3 поддерживает аннотации типов, в Python 2 их нет.
Важный факт: поддержка Python 2 была официально прекращена 1 января 2020 года. Сегодня используется исключительно Python 3. Актуальными на 2026 год являются версии 3.14 и 3.15.
Почему Python популярен
Его сильные стороны — простота и читаемость кода, универсальность, обширная стандартная библиотека и активное сообщество разработчиков. Python широко применяется в веб-разработке (фреймворки Django, Flask), анализе данных и машинном обучении (библиотеки Pandas, TensorFlow), автоматизации задач, создании десктопных приложений и в других областях.
Философия и развитие
Философия Python отражена в документе «The Zen of Python» («Дзен Пайтона»), который был сформулирован Тимом Питерсом в 1999 году. В интерпретаторе Python этот свод правил можно вывести командой import this
С 2001 года развитием языка занимается некоммерческая организация Python Software Foundation, которая отвечает за выпуск новых версий, контроль интеллектуальных прав и популяризацию языка. В 2018 году Гвидо ван Россум передал часть своих полномочий сообществу, и с тех пор развитие Python полностью осуществляется коллективно.

2. В чем разница между модулем и пакетом?
Разница между модулем и пакетом в Python заключается в уровне абстракции и способе организации кода.
Модуль
Модуль — это отдельный файл с кодом на Python, имеющий расширение .py. Внутри этого файла могут находиться функции, классы, переменные и исполняемый код. Имя модуля соответствует имени файла без расширения.
Пример: файл utils.py — это модуль. Чтобы его использовать, другой код импортирует этот модуль: import utils
Ключевые особенности:
	Создаёт собственное пространство имён для предотвращения конфликтов с глобальными переменными других модулей.
	Может быть написан не только на Python, но и на C (модули расширения) или быть встроенным в интерпретатор.
	При первом импорте модуль выполняется целиком, и его код инициализируется.
Пакет
Пакет — это способ структурирования группы связанных модулей в виде директории. Чтобы Python распознал каталог как пакет, в нём должен находиться специальный файл __init__.py. Этот файл может быть пустым или содержать код инициализации пакета.



Пример структуры пакета:
mypackage/
├── __init__.py
├── submodule1.py
└── submodule2.py
Ключевые особенности:
	Позволяет группировать модули по тематикам или функциональным блокам.
	Создаёт иерархическую структуру пространства имён, что помогает избежать конфликтов имён модулей с одинаковыми названиями в разных частях проекта.
	Может содержать вложенные подпакеты, образуя дерево директорий.
	С помощью __init__.py
 можно, например, сделать доступными на уровне пакета какие-то конкретные модули или функции.
Важно: с версии Python 3.3 любая папка без __init__.py
 также считается пакетом (так называемые namespace-пакеты).
Сравнение в таблице
Критерий	Модуль	Пакет
Что это	Один файл с кодом на Python	Директория, содержащая модули и/или другие пакеты
Назначение	Единица повторного использования кода	Способ структурирования кода в крупные логические группы
Пример	math.py, datetime.py	Стандартная библиотека json, пользовательский пакет с модулями для работы с JSON
Импорт	import math	import mypackage.module1 или from mypackage import module
Таким образом, модуль — это базовый строительный блок, а пакет — инструмент для удобной организации этих блоков в крупные, масштабируемые проекты.







3. Что такое структура данных? Приведите примеры из жизни и программирования.
Структура данных — это способ организации и хранения информации в компьютере, который позволяет эффективно выполнять операции над этими данными: добавлять, удалять, искать, сортировать и так далее. Проще говоря, это «контейнер», который задаёт правила, как элементы должны быть расположены и как с ними можно работать.
Примеры из жизни
	Стек (LIFO — Last In, First Out, «последним пришёл — первым ушёл»). Представьте стопку книг или тарелку, которую вы кладёте в посудомоечную машину. Чтобы достать книгу или тарелку сверху, нужно сначала снять все, лежащие сверху. В жизни это встречается часто: механизм отмены действия в текстовом редакторе (вы сохраняете каждое отменённое действие в стек), обратный порядок обработки задач в системе с приоритетами (сначала выполняются последние добавленные задачи).
	Очередь (FIFO — First In, First Out, «первым пришёл — первым ушёл»). Классический пример — очередь людей в билетную кассу. Человек, который встал в конец очереди, будет обслужен последним. В программировании очереди используют для планирования процессов: например, задачи в очереди на обработку на сервере или обработка пакетов в сети.
	Дерево. Генеалогическое древо, структура папок на компьютере или организация файловой системы — всё это примеры деревьев. В программировании деревья используют для хранения иерархических данных, например, в словарях поиска или в алгоритмах сортировки.
Примеры в Python
В Python есть несколько встроенных структур данных, каждая из которых подходит для своих задач:
Структура данных	Что это	Когда использовать
Список (list)	Изменяемая, упорядоченная коллекция элементов.	Когда нужно хранить коллекцию объектов (например, список товаров в корзине) и при этом иметь возможность менять этот список (добавлять, удалять элементы).
Кортеж (tuple)	Похож на список, но неизменяем (элементы нельзя менять после создания).	Когда нужно хранить набор связанных значений, которые не должны изменяться (например, координаты точки или месяцы года).
Словарь (dict)	Коллекция пар «ключ-значение».	Для быстрого доступа к данным по уникальному ключу (например, хранение профиля пользователя с его настройками).
Множество (set)	Неупорядоченная коллекция уникальных элементов.	Когда нужно выполнить математические операции над данными (объединение, пересечение) или просто проверить наличие элемента.
Деке (deque)	Двусторонняя очередь. Эффективен для операций добавления и удаления элементов с обоих концов.	Для реализации очереди, например, при обработке задач с возможностью работы как с началом, так и с концом очереди.
Пример кода:
# Создание разных структур данных
fruits = ["яблоко", "банан", "апельсин"]  # Список - изменяемая коллекция
colors = ("красный", "синий")          # Кортеж - неизменяемая коллекция
user = {"name": "Иван", "age": 30}         # Словарь - коллекция пар "ключ-значение"
numbers = {1, 2, 3, 2, 1}                   # Множество - уникальные элементы

# Работа со списком
fruits.append("груша")  # Список изменяем

# Работа с кортежем
# colors = "зелёный"  # Ошибка: кортежи неизменяемы

# Работа со словатором
user["city"] = "Москва"

# Работа с множеством
unique_colors = colors - {"красный"}  # Множество - уникальные элементы
Выбор конкретной структуры данных зависит от задачи: нужно ли вам упорядоченное хранение (список, кортеж), быстрый доступ по ключу (словарь), проверка на уникальность (множество) или специфический порядок обработки (стек, очередь).

4. Встроенные структуры данных Python:
	Какие есть примитивные типы данных в Python?
	Какие есть коллекции в Python?
	Какие типы данных изменяемы, а какие нет?


В Python встроенные структуры данных делятся на примитивные (скалярные) типы и коллекции (составные типы). Давайте разберём каждый вопрос подробно.
Примитивные типы данных
Это базовые, неделимые типы, которые хранят одно значение. В Python к ним относятся:
	int  — целые числа (в Python имеют произвольную точность).
	float  — числа с плавающей точкой.
	complex — комплексные числа.
	bool — логический тип с значениями True и False.
	str  — последовательности символов, строки.
	NoneType — специальный тип для единственного значения None.
Важный нюанс: все примитивные типы в Python неизменяемы. Это значит, что после создания объекта его значение нельзя изменить — любая операция с ним создаст новый объект.
Коллекции (составные типы)
Коллекции предназначены для хранения набора значений. В Python есть несколько встроенных коллекций:
	list — упорядоченная изменяемая последовательность элементов.
	tuple — упорядоченная неизменяемая последовательность элементов.
	set — неупорядоченная коллекция уникальных элементов.
	frozenset  — неизменяемое множество.
	dict — коллекция пар «ключ-значение».
Изменяемость типов данных
Ключевое различие между типами данных в Python — возможность изменения их содержимого после создания.
Тип данных	Изменяемость	Пояснение
int,float,complex,
bool,str,tuple,
frozenset,NoneType	Неизменяемые	После создания объекта его содержимое нельзя изменить. Любая операция создаёт новый объект.
list, dict, set,
bytearray,
memoryview	Изменяемые	Содержимое объекта можно менять «на месте», не создавая новый объект. senjun.rupurpleschool.ru
Пример, демонстрирующий разницу:
# Неизменяемый объект (число)
x = 10
print(id(x))  # Уникальный идентификатор объекта
x += 5
print(id(x))  # Новый идентификатор, так как создан новый объект

# Изменяемый объект (список)
lst = [1, 2, 3]
print(id(lst))  # Уникальный идентификатор списка
lst.append(4)
print(id(lst))  # Тот же идентификатор, список изменён на месте
Что важно помнить
	Неизменяемые объекты безопаснее для передачи в функции и работы в многопоточных приложениях, так как гарантируют, что данные не будут случайно изменены.
	Изменяемые объекты позволяют эффективно работать с динамическими данными, но требуют более внимательного подхода к управлению состоянием.
	При работе с вложенными структурами (например, список из списков) для явного копирования нужно использовать copy.copy()  или  copy.deepcopy().
5. Хэшируемость: что это такое, какие типы данных хэшируемы, зачем это нужно?
Хэшируемость в Python — это свойство объекта иметь хэш-значение (число или строку), которое не меняется в течение всего срока его жизни. Чтобы объект был хэшируемым, в его классе должны быть реализованы два метода: __hash__() (для вычисления хэша) и __eq__() (для сравнения на равенство). При этом объекты, которые считаются равными, обязаны иметь одинаковое хэш-значение.
Какие типы данных хэшируемы
Хэшируемыми в Python являются:
	Все неизменяемые встроенные типы. Это числа (int, float, complex), строки (str), байтовые строки (bytes), frozenset, а также кортежи (tuple) — но только если все их элементы хэшируемы.
	Замороженные множества (frozensset). Они всегда хэшируемы, и для этого достаточно, чтобы все их элементы были хэшируемыми.
	Пользовательские классы. По умолчанию экземпляры классов хэшируемы: их хэш-значение вычисляется на основе идентификатора объекта (id()), и все такие объекты считаются неравными (кроме случаев, когда это один и тот же объект).
Нехэшируемыми являются все изменяемые контейнеры, то есть типы, которые можно модифицировать после создания:
	списки (list);    словари (dict);     множества (set).

Зачем это нужно
Главное практическое следствие хэшируемости — возможность использовать объект в качестве ключа в словаре или элемента в множестве. Эти структуры данных в Python реализованы на основе хэш-таблиц. Хэш-таблица использует хэш-значение ключа для быстрого вычисления позиции элемента в массиве, что обеспечивает константное время доступа (O(1)). Если бы ключ мог менять своё хэш-значение (например, потому что он был изменяемым), то после изменения объекта его «адрес» в таблице изменился бы, и поиск элемента перестал бы работать корректно. docs.python.orghabr.comvc.rustackoverflow.com
Пример:
# Хэшируемый ключ (строка)
d = { "name": "Alice", "age": 30 }
# Хэшируемый элемент в множестве
s = { "apple", "banana", "orange" }
# Нехэшируемый ключ (список) — ошибка
# d["new_key"] = "value"  # TypeError
# Нехэшируемый элемент в множестве (список) — ошибка
# s.add([1, 2, 3])  # TypeError
Таким образом, хэшируемость — это техническое условие, которое позволяет Python эффективно работать со словарями и множествами, обеспечивая быстрый поиск и уникальность элементов.

6. Операции над структурами данных: доступ, вставка, удаление, поиск - попрактиковать различия в каждой коллекции, знать разницу!
В Python четыре основные встроенные коллекции: список (list), кортеж (tuple), словарь (dict) и множество (set). У каждой свои особенности, и выбор зависит от задачи: нужно ли сохранять порядок элементов, разрешены ли изменения, как быстро выполнять доступ, вставку, удаление и поиск.
Списки (list)
Доступ: по индексу (начиная с 0) или срезам.
Вставка: append() — в конец, insert(i, x) — на позицию i.
Удаление: remove(x) — первое вхождение, pop(i) — элемент по индексу и возврат, del — по индексу или срезу.
Поиск: in (проверка наличия), index(x) (индекс первого вхождения).
Особенности: изменяемая упорядоченная коллекция.
Пример:
fruits = ["яблоко", "банан", "вишня"]
fruits.append("апельсин")  # Вставка в конец
fruits.insert(1, "груша")   # Вставка на позицию 1
print(fruits.pop(1))        # Удаление и возврат элемента с индексом 1
Кортежи (tuple)
Доступ: по индексу (с 0 или с конца).
Вставка: нельзя изменить на месте — создаётся новый кортеж (например, через конкатенацию срезов).
Удаление: нельзя удалить элемент — создаётся новый кортеж.
 Поиск: in и методы index(),count().
Особенности: неизменяемая упорядоченная коллекция. Подходит для данных, которые не должны меняться (координаты, дни недели).
Пример:
t = (1, 2, 3)
# new_t = t + (4,)  # Создание нового кортежа
Словари (dict)
Доступ: по ключу (квадратные скобки). Для безопасного доступа используйте get().
Вставка: присваиванием dict[key] = value.
 Удаление: del dict[key] или pop(key[, default]).
 Поиск: in проверяет наличие ключа.
Пример:
capitals = {'Russia': 'Moscow', 'Ukraine': 'Kiev'}
print(capitals['Russia'])  # Доступ по ключу
del capitals['Ukraine']      # Удаление
city = capitals.get('France', 'не найдено')  # Безопасный доступ
Множества (set)
Доступ: невозможен по индексу — множества неупорядочены.
 Вставка: add(x).
 Удаление: remove(x) (вызывает ошибку, если элемента нет), discard(x) (безопасно),pop() (удаляет и возвращает произвольный элемент).
 Поиск: in. Особенности: неупорядоченная коллекция уникальных элементов.
Пример:
s = {1, 2, 3, 2, 1}  # Автоматически удаляются дубликаты
print(s)  # {1, 2, 3}
s.add(4)
s.discard(2)  # Безопасно, если элемента нет
Сравнение в таблице

Когда что использовать?
	Списки — когда нужна упорядоченная коллекция, которую планируется изменять (часто — для списков покупок, логов).
	Кортежи — для данных, которые не должны меняться: координаты, дни недели, параметры функции.

7. Что такое алгоритм? Зачем они нужны?
Алгоритм — это чёткая, конечная последовательность шагов (инструкций), которая решает какую-то задачу. Проще говоря, это план действий: вы определяете, какие данные нужны, какие операции с ними выполнить и какой результат получить.
В программировании алгоритм — это мост между самой задачей и кодом. Сначала вы продумываете логику (шаги решения), а уже потом записываете её на языке Python.
Зачем они нужны в Python?
	Помогают структурировать решение. Часто задачу сложно решить сразу целиком. Алгоритм позволяет разбить её на мелкие, управляемые шаги.
	Делают код понятнее. Когда логика решения чётко прописана словами (а ещё лучше — в виде блок-схемы), другим разработчикам (и вам самим через некоторое время) гораздо проще понять, что делает программа.
	Позволяют находить эффективные решения. Для одной и той же задачи можно написать код разными алгоритмами. Одни будут работать быстрее на больших данных, другие — использовать меньше памяти. Например, для поиска элемента в списке линейный поиск (перебор всех элементов) работает медленно, а бинарный поиск (но он требует, чтобы список был отсортирован) — гораздо быстрее. Или разные алгоритмы сортировки (пузырьковая, быстрая, слияние) имеют разную сложность.
	Служат фундаментом для сложных задач. В более серьёзных проектах (машинное обучение, обработка больших данных, веб-разработка) алгоритмы комбинируют, чтобы решать нетривиальные проблемы.
	Часто проверяют на собеседованиях. Умение описать алгоритм, проанализировать его сложность и предложить оптимизацию — важный навык для Python-разработчика.
Небольшой пример
Допустим, задача: найти сумму всех чисел в списке. Алгоритм будет таким:
	Создать переменную для суммы и присвоить ей 0.
	Пройти по каждому числу в списке.
	Добавить текущее число к сумме.
	Вывести результат.
А вот как это запишут на Python:
numbers = [3, 7, 10, 4]
total = 0
for number in numbers:
    total += number
print(total)
Здесь мы реализовали тот самый алгоритм на языке Python. startoria.org
Какие бывают базовые типы?
В программировании обычно выделяют такие типы:
	Линейный — действия выполняются строго по очереди.
	С условием (ветвление) — в зависимости от результата проверки условия (if) программа выбирает один из путей.
	Циклический — некоторые шаги повторяются несколько раз (с помощью циклов for или while).
Позже вы познакомитесь и с более продвинутыми подходами: рекурсией, динамическим программированием, методами «разделяй и властвуй».
Так что не пугайтесь! Начните с простых задач, и постепенно вы начнёте видеть алгоритмы повсюду — даже в том коде, который пишете каждый день. Хотите разобрать какой-нибудь конкретный пример (сортировку, поиск или что-то ещё)? Напишите — разложим по шагам!





8. Оценка сложности алгоритмов: Big O notation (асимптотика).
Оценка сложности алгоритмов с помощью Big O notation — это фундаментальный инструмент в информатике, который помогает понять, как алгоритм будет вести себя при увеличении объёма данных. В Python этот подход позволяет сравнивать эффективность разных решений одной задачи и выбирать наиболее масштабируемое.
Что такое Big O?
Big O — это математическая нотация, которая описывает верхнюю границу роста времени выполнения или пространства (памяти) алгоритма в худшем случае. Она показывает, как время работы или объём памяти растёт с увеличением размера входных данных (обозначается как n). Формально запись O(f(n)) означает, что время выполнения алгоритма растёт не быстрее, чем функция f(n) при достаточно больших n
Ключевые принципы асимптотического анализа
При оценке сложности с помощью Big O принято придерживаться нескольких правил:
	Фокус на скорости роста. Важен не абсолютный временной показатель, а то, как он меняется при росте n.
	Игнорирование констант. Множители и слагаемые, не зависящие от n, опускаются, так как при больших объёмах данных их влияние становится незначительным. Например, O(2n) эквивалентно O(n).
	Учёт доминирующих членов. В сложных выражениях оставляется только член с самым быстрым ростом. Например, O(n² + n) прощается до O(n²).
	Анализ наихудшего сценария. Big O описывает именно худший случай, что даёт гарантию производительности в любых входных данных.
Основные классы сложности
Название	Сложность	Пример
Константная	O(1)	Доступ к элементу списка по индексу, операция присваивания
Логарифмическая	O(log n)	Бинарный поиск в отсортированном списке
Линейная	O(n)	Линейный поиск в несортированном списке (в худшем случае нужно проверить все элементы)
Линейно-логарифмическая	O(n log n)	Сортировка слиянием, быстрая сортировка
Квадратичная	O(n²)	Пузырьковая сортировка, сортировка выбором
Экспоненциальная	O(2^n)	Рекурсивный алгоритм Фибоначчи без мемоизации
Факториальная	O(n!)	Генерация всех перестановок списка
Как оценивать сложность в коде на Python?
Чтобы проанализировать код, нужно:
	Определить параметр n. Это обычно размер входных данных.
	Выделить базовые операции. Это те действия, которые доминируют во времени выполнения (например, сравнения в сортировке).
	Выразить количество операций как функцию от n.
	Упростить функцию, отбросив константы и менее значимые слагаемые.
Пример:
def search_unsorted_list(lst, target):
    for item in lst:  # Цикл выполняется n раз
        if item == target:  # В худшем случае элемент на последней позиции
            return True
    return False
Здесь сложность — O(n), так как в худшем случае алгоритм просматривает весь список.
Важные нюансы
	Пространственная сложность. Помимо времени, оценивают и память, которую алгоритм использует. Например, создание копии списка требует O(n) дополнительной памяти.
	Разные случаи. Для одного и того же алгоритма возможны разные сценарии: лучший (O(1) — элемент в начале списка), средний и худший (O(n)). Big O обычно описывает худший случай.
	Другие нотации. Помимо O, существуют и другие обозначения: Ω (омега, описывает нижнюю границу — лучший случай) и Θ (тета, даёт точную оценку, когда верхняя и нижняя границы совпадают).
Вывод
Big O — мощный инструмент для выбора правильного алгоритма. Он помогает избежать «медленных» решений на этапе проектирования, когда вы ещё не запустили код на реальных данных. В Python, зная сложности встроенных операций со структурами данных (списки, словари, множества), вы можете писать более эффективный код.

Временная сложность операций в встроенных типах данных Python описывается с помощью нотации «O большое» (Big O). Она показывает, как время выполнения операции растёт с увеличением размера структуры данных.

10. Алгоритмы поиска: линейный, бинарный (и когда какой применять).
Линейный и бинарный поиски — два фундаментальных алгоритма, которые решают задачу нахождения элемента в коллекции, но принципиально различаются по условиям применения и эффективности.
Линейный поиск
Принцип работы: алгоритм последовательно проверяет каждый элемент коллекции, пока не найдёт элемент, равный искомому, или не дойдёт до конца коллекции.
Когда применять:
	Коллекция может быть в любом порядке (не отсортирована).
	Массив или список небольшой.
	Поиск выполняется однократно.
Временная сложность: O(n) в худшем и среднем случаях (где n — количество элементов в коллекции). В лучшем случае (если элемент оказался первым) сложность составляет O(1).
Пример реализации на Python:
def linear_search(arr, target):
    for i, element in enumerate(arr):
        if element == target:
            return i  # Возвращает индекс найденного элемента
    return -1  # Возвращает -1, если элемент не найден
Плюсы:
	Простота реализации.
	Не требует дополнительной памяти.
Минусы:
	Низкая эффективность для больших коллекций.
Бинарный поиск
Принцип работы: алгоритм работает только с отсортированными коллекциями. На каждом шаге он делит текущую область поиска пополам и отбрасывает ту половину, в которой искомого элемента заведомо нет.
Когда применять:
	Коллекция отсортирована.
	Данные статичны (коллекция не меняется после построения).
	Поиск выполняется многократно на больших наборах данных.
Временная сложность: O(log n) в худшем и среднем случаях.
Пример реализации на Python (итеративный подход):
def binary_search(arr, target):
    left = 0
    right = len(arr) - 1

    while left <= right:
        mid = (left + right) // 2  # Вычисляем средний индекс
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1  # Ищем в правой половине
        else:
            right = mid - 1  # Ищем в левой половине
    return -1  # Элемент не найден
Важный нюанс: стандартный бинарный поиск не гарантирует, какое из дублирующихся значений будет возвращено. Если требуется найти, например, первое или последнее вхождение, используются модификации (lower_bound, upper_bound). habr.com
Плюсы:
	Высокая эффективность для больших отсортированных коллекций. foxford.rusky.pro
Минусы:
	Обязательное условие — сортировка данных. foxford.rufreecodecamp.org
	Если коллекция часто меняется (элементы добавляются/удаляются), поддержание отсортированности требует затрат, что может сделать бинарный поиск менее выгодным по сравнению с другими структурами данных. sky.pro
Когда что выбрать?
Ситуация	Рекомендуемый алгоритм
Коллекция не отсортирована или неизвестна	Линейный поиск
Коллекция отсортирована и поиск выполняется многократно на больших данных	Бинарный поиск
Данные часто меняются (много вставок/удалений)	Рассмотрите другие структуры данных (например, хеш-таблицы)
Практический совет для Python
В стандартной библиотеке Python есть модуль bisect, который предоставляет оптимизированные функции для работы с отсортированными списками, включая бинарный поиск. Это часто является предпочтительным вариантом, так как bisect  написан на C и работает быстрее самописного решения.
import bisect
def find_position(arr, target):
    # Находим индекс так, чтобы порядок в массиве не нарушался
    pos = bisect.bisect_left(arr, target)
    if pos < len(arr) and arr[pos] == target:
        return pos
    return -1
Этот подход сочетает сортировку с помощью
bisect и поиск за логарифмическое время.
Главное — всегда оценивать контекст: размер данных, их изменчивость и частоту поисковых операций.

11. Алгоритмы сортировки: пузырьковая, вставками, встроенная sorted() (Timsort), быстрая сортировка, сортировка слиянием (кратко).
В Python для сортировки используются встроенные функции и методы, которые реализуют эффективные алгоритмы. Давайте кратко рассмотрим каждый из них.
1. Пузырьковая сортировка (Bubble Sort)
Суть: многократно проходит по списку, сравнивает соседние элементы и меняет их местами, если они стоят в неправильном порядке. На каждом проходе наибольший элемент «всплывает» в конец списка.
Сложность:
	Худший и средний случаи: O(n²).
	Лучший случай (с оптимизацией): O(n) — если список уже отсортирован.
Код на Python:
def bubble_sort(arr):
    n = len(arr)
    for i in range(n):
        swapped = False  # Флаг для оптимизации
        for j in range(0, n - i - 1):
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
                swapped = True
        if not swapped:  # Если обменов не было, список отсортирован
            break
    return arr
Когда использовать: в основном для образовательных целей или сортировки очень маленьких массивов.
2. Сортировка вставками (Insertion Sort)
Суть: строит отсортированную последовательность, постепенно вставляя элементы из неотсортированной части в правильные позиции в отсортированной части.
Сложность:
	Худший и средний случаи: O(n²).
	Лучший случай (почти отсортированные данные): O(n).
Код на Python:
def insertion_sort(arr):
    for i in range(1, len(arr)):
        key = arr[i]  # Элемент, который вставляем
        j = i - 1
        # Сдвигаем элементы, которые больше key, вправо
        while j >= 0 and arr[j] > key:
            arr[j + 1] = arr[j]
            j -= 1
        arr[j + 1] = key  # Вставляем key на освободившееся место
    return arr
Когда использовать: для небольших массивов или когда данные почти отсортированы.
3. Встроенная сортировка (Timsort)
Суть: гибридный алгоритм, который сочетает сортировку вставками и слиянием. Он хорошо работает на реальных данных, в том числе на частично отсортированных.
Особенности:
	Сложность: O(n log n) в худшем случае.
	Стабильность: сохраняет относительный порядок элементов с одинаковыми ключами.
	Реализован на C, поэтому работает быстрее многих пользовательских реализаций на Python.
Как использовать в Python:
	Функция sorted()  — возвращает новый отсортированный список, не изменяя исходный.
	Метод list.sort()  — сортирует список на месте (изменяет исходный список).
4. Быстрая сортировка (Quick Sort)
Суть: алгоритм «разделяй и властвуй». Выбирается опорный элемент (pivot), массив разделяется на две части: элементы меньше pivot и элементы больше pivot. Затем рекурсивно сортируются обе части.
Сложность:
	В среднем случае: O(n log n).
	В худшем случае: O(n²) — если опорный элемент всегда наименьший или наибольший (например, при уже отсортированном массиве).
Код на Python (простая версия):
def quick_sort(arr):
    if len(arr) <= 1:
        return arr
    pivot = arr[len(arr) // 2]  # Выбираем средний элемент как опорный
    left = [x for x in arr if x < pivot]
    middle = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]
    return quick_sort(left) + middle + quick_sort(right)
Важно: эта версия создаёт новые списки, что увеличивает потребление памяти. Для оптимизации часто используют сортировку на месте (in-place). foxford.ru
5. Сортировка слиянием (Merge Sort)
Суть: также «разделяй и властвуй». Массив рекурсивно делится на две половины, пока не останутся массивы длиной 1, затем эти массивы сливаются в отсортированном порядке.
Сложность:
	Всегда: O(n log n).
	Пространственная сложность: O(n).
	Стабильность: да.
Код на Python:
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])
    return merge(left, right)

def merge(left, right):
    result =
    i = j = 0
    # Сливаем два отсортированных массива
    while i < len(left) and j < len(right):
        if left[i] < right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    # Добавляем оставшиеся элементы
    result.extend(left[i:])
    result.extend(right[j:])
    return result
```

**Когда использовать:** когда важна стабильность сортировки и гарантированная эффективность на больших массивах. [5](https://sprintcode.pro/ru/blog/sorting-algorithms-python)
## Какой алгоритм выбрать?
* **Для реальных задач:** используйте встроенные `sorted()` или `sort()` — они оптимизированы и надёжны.
* **Для учебных целей:** реализуйте простые алгоритмы (пузырьком, вставками) для понимания основ.
* **Для больших массивов:** выбирайте быструю сортировку или сортировку слиянием из-за их предсказуемой сложности O(n log n).
Если хотите, могу подробнее разобрать, как выбрать опорный элемент в быстрой сортировке или как оптимизировать память в сортировке слиянием.

12. Какие еще есть алгоритмы сортировки?
Вот ещё несколько популярных алгоритмов сортировки — с краткой сутью, сложностью и особенностями применения в Python.
Сортировка выбором (Selection Sort)
Суть: на каждом шаге ищем минимальный элемент в неотсортированной части и ставим его в конец отсортированной.
Сложность: O(n²) во всех случаях.
Плюсы/минусы: простая реализация, но неэффективна на больших массивах.
python
ПереноситьСвернутьКопировать
def selection_sort(arr):
    n = len(arr)
    for i in range(n):
        min_idx = i
        for j in range(i + 1, n):
            if arr[j] < arr[min_idx]:
                min_idx = j
        arr[i], arr[min_idx] = arr[min_idx], arr[i]
    return arr

Шейкерная (коктейльная) сортировка (Cocktail Sort)
Суть: улучшенная пузырьковая: проходит по массиву туда и обратно, «выталкивая» и максимум в конец, и минимум в начало.
Сложность: в худшем случае O(n²), но на частично упорядоченных данных работает лучше обычной пузырьковой.
Когда полезна: для небольших массивов, где важна простота и чуть лучшая производительность, чем у Bubble Sort.
________________________________________
Сортировка кучей (Heap Sort)
Суть: строится бинарная куча (обычно max-heap), затем последовательно извлекаются максимальные элементы.
Сложность: O(n log n) всегда, дополнительная память O(1).
Особенности: не стабильная (может менять порядок равных элементов), но предсказуема по времени. В Python можно использовать модуль heapq.
python

import heapq

def heap_sort(arr):
    heapq.heapify(arr)  # превращает список в кучу за O(n)
    return [heapq.heappop(arr) for _ in range(len(arr))]
________________________________________
Сортировка Шелла (Shell Sort)
Суть: обобщение сортировки вставками: сначала сортируются элементы, отстоящие далеко друг от друга, затем шаг уменьшается.
Сложность: зависит от последовательности шагов; часто оценивают как между O(n log² n) и O(n³/²).
Плюсы: работает быстрее вставки на больших массивах, не требует много памяти.
________________________________________
Сортировка подсчётом (Counting Sort)
Суть: подсчитывается количество каждого значения, затем массив восстанавливается в порядке возрастания.
Сложность: O(n + k), где k — диапазон значений.
Ограничения: подходит для целых чисел с небольшим диапазоном.
Пример:
python
ПереноситьСвернутьКопировать
def counting_sort(arr):
    if not arr:
        return arr
    min_val = min(arr)
    max_val = max(arr)
    k = max_val - min_val + 1
    count = [0] * k

    for x in arr:
        count[x - min_val] += 1

    result = []
    for i, c in enumerate(count):
        result.extend([i + min_val] * c)
    return result
________________________________________
Поразрядная сортировка (Radix Sort)
Суть: сортирует числа по разрядам (сначала по младшему, потом по старшему, либо наоборот), используя стабильную сортировку на каждом шаге (часто Counting Sort).
Сложность: O(d·(n + k)), где d — число разрядов, k — основание системы счисления (обычно 10).
Применение: целые числа, иногда строки фиксированной длины.
________________________________________
Блочная (корзинная) сортировка (Bucket Sort)
Суть: элементы распределяются по «корзинам» (buckets) в зависимости от значения, каждая корзина сортируется отдельно (часто вставками), затем корзины объединяются.
Сложность: в среднем O(n), если данные равномерно распределены; в худшем — O(n²).
Подходит для: вещественных чисел из диапазона [0, 1) или равномерно распределённых данных.
________________________________________
Топологическая сортировка
Особенность: это не сортировка чисел «по величине», а упорядочивание вершин ориентированного ациклического графа (DAG) так, чтобы для любого ребра u→v вершина u шла раньше v.
Где используется: планирование задач, сборка проектов (например, порядок компиляции файлов).
________________________________________
Как выбирать алгоритм
	Для практики и понимания: Bubble, Selection, Insertion — простые и наглядные.
	Для реальных задач в Python: почти всегда sorted() / list.sort() (Timsort) — это оптимально и надёжно.
	Особые случаи:
	маленькие диапазоны целых чисел — Counting Sort;
	длинные последовательности целых с фиксированной разрядностью — Radix Sort;
	нужно мало памяти и гарантированное O(n log n) — Heap Sort;
	данные в виде графа зависимостей — топологическая сортировка.

Теория — Дополнительные вопросы
1. Linked List: что это, какими бывают, где применяются?
Linked List (связный список)
Linked List — это линейная структура данных, где элементы (узлы) не хранятся подряд в памяти, а связаны между собой ссылками (указателями).
Каждый узел обычно содержит:
	данные (значение);
	ссылку на следующий узел (а в некоторых типах — ещё и на предыдущий).
В отличие от массива, связному списку не нужна непрерывная область памяти: узлы могут быть разбросаны по разным адресам, а порядок определяется ссылками.
________________________________________
Виды связных списков
	Односвязный список (Singly Linked List)
В каждом узле — данные и ссылка только на следующий элемент. Проход возможен только вперёд. Конец списка обозначается None (или null).
python
class Node:
    def __init__(self, data):
        self.data = data
        self.next = None
	Двусвязный список (Doubly Linked List)
Узел хранит ссылки и на следующий, и на предыдущий элемент. Это позволяет двигаться в обоих направлениях и упрощает удаление/перестановку узлов.
python
class Node:
    def __init__(self, data):
        self.data = data
        self.next = None
        self.prev = None
	Циклический (кольцевой) список (Circular Linked List)
Последний узел ссылается не на None, а на первый. Бывает односвязным или двусвязным. Удобно для циклических процессов (например, планирование задач).
	XOR связный список (редкий вариант)
Использует трюк с XOR адресов, чтобы хранить «предыдущий и следующий» в одном поле. Экономит память, но усложняет реализацию и отладку. На практике почти не используется.
	Список с пропусками (Skip List)
Это уже не «чистый» связный список, а структура на базе связных списков с несколькими уровнями ссылок для ускорения поиска (в среднем O(log n)). Часто применяется как альтернатива сбалансированным деревьям.
Основные операции и их сложность
	Вставка в начало: O(1)
	Удаление из начала: O(1)
	Вставка/удаление в середине (если уже есть указатель на нужный узел): O(1), но поиск позиции — O(n)
	Поиск по значению: O(n) (последовательный проход)
	Доступ по индексу: O(n) — нет прямого доступа, как у массива
Где применяются связные списки
	Стеки и очереди
Связный список — естественная реализация стека (LIFO) и очереди (FIFO), особенно когда размер заранее неизвестен.
	Хеширование: метод цепочек
При коллизиях в хеш таблице элементы с одинаковым хешем хранят в связном списке. В Python словари и set используют более продвинутые методы, но идея цепочек — классическая.
	Графы: списки смежности
Для каждой вершины хранят список соседей. Это удобно и экономно по памяти для разреженных графов.
	История браузера («Назад/Вперёд»)
Двусвязный список позволяет легко перемещаться между предыдущими и следующими страницами.
	Кэш LRU (Least Recently Used)
Комбинация хеш таблицы и двусвязного списка даёт O(1) для доступа, перемещения и удаления «старых» элементов. Именно так часто реализуют LRU кэш.
	Буферы и потоковая обработка
Кольцевые списки применяют в кольцевых буферах (аудио/видео, логирование), где данные перезаписываются по кругу.
	Текстовые редакторы и системы версионирования
Иногда связные списки используют для хранения фрагментов текста или изменений, чтобы быстро вставлять/удалять куски без копирования больших массивов.
	Операционные системы: планирование процессов
Циклические списки удобны для алгоритмов типа Round Robin: процессы идут по кругу, каждый получает квант времени.

Плюсы и минусы по сравнению с массивами
Плюсы:
	Быстрая вставка/удаление в начале и при известном узле (O(1)).
	Размер динамический, не нужно заранее выделять большой блок памяти.
	Узлы могут быть разбросаны в памяти — это полезно, когда непрерывной памяти мало.
Минусы:
	Нет произвольного доступа по индексу: чтобы добраться до k го элемента, нужно пройти от начала (O(n)).
	Больше памяти на хранение ссылок (особенно в двусвязных списках).
	Хуже локальность данных: узлы разбросаны, кэш процессора работает менее эффективно.
Пример простого односвязного списка на Python
python
class Node:
    def __init__(self, data):
        self.data = data
        self.next = None

class LinkedList:
    def __init__(self):
        self.head = None

    def append(self, data):
        new_node = Node(data)
        if not self.head:
            self.head = new_node
            return
        cur = self.head
        while cur.next:
            cur = cur.next
        cur.next = new_node

    def prepend(self, data):
        new_node = Node(data)
        new_node.next = self.head
        self.head = new_node

    def display(self):
        cur = self.head
        while cur:
            print(cur.data, end=" -> ")
            cur = cur.next
        print("None")

2. Деревья (binary tree, BST, heap), графы, trie: обзор, где применяются, какие есть реализации?
Деревья
Бинарное дерево (Binary Tree) — структура, где у каждого узла не более двух потомков: левого и правого. Само по себе оно не гарантирует эффективности поиска, если не соблюдать дополнительные правила.

Где применяют: как основу для других структур, для представления иерархических данных (например, файловая система), в некоторых алгоритмах сжатия (дерево Хаффмана).
Реализация: обычно через класс узла с полями left и right (ссылки на потомков) и корнем дерева.
Бинарное дерево поиска (BST) — частный случай бинарного дерева. Для каждого узла выполняется правило: все значения в левом поддереве меньше значения узла, а в правом — больше. Это позволяет эффективно искать, вставлять и удалять элементы.
Где применяют: для реализации словарей (Map/Dictionary), когда нужно быстро искать, добавлять и удалять элементы, сохраняя их в отсортированном виде.
Реализация: аналогично бинарному дереву, но при вставке и удалении строго соблюдается правило BST.
Самобалансирующиеся BST. Проблема обычного BST в том, что при последовательной вставке (например, в уже отсортированном массиве) дерево вырождается в связный список, и сложность операций падает до O(n). Поэтому используют самобалансирующиеся варианты:
	AVL-дерево. Для каждого узла разница высот левого и правого поддеревьев не превышает 1. При нарушении баланса выполняются повороты.
	Красно-чёрное дерево. Каждый узел имеет цвет (красный или чёрный). Соблюдаются правила, которые гарантируют, что дерево остаётся примерно сбалансированным.
Куча (Heap) — это специализированное дерево, обычно бинарное, которое удовлетворяет свойству кучи: в min-heap значение каждого узла меньше или равно значениям его потомков, а в max-heap — больше или равно.
Где применяют:
	Для реализации приоритетных очередей (элементы с высшим приоритетом извлекаются первыми).
	В алгоритме сортировки кучей (Heapsort).
	В алгоритмах на графах: Дейкстры (поиск кратчайшего пути), Прима (построение минимального остовного дерева).
	Для нахождения k-го наименьшего/наибольшего элемента в массиве.
Реализация: часто используют массив. Отношения «родитель-потомок» вычисляются по индексам: для элемента с индексом i родитель — ⌊(i-1)/2⌋, левый потомок — 2i+1, правый — 2i+2. Операции вставки и извлечения поддерживают свойство кучи с помощью «просеивания» (sift-up/sift-down).
Графы

Граф — структура из вершин (узлов) и рёбер (связей между ними). Графы моделируют любые отношения «объект-связь».
Виды: ориентированные (рёбра имеют направление) и неориентированные (связи двусторонние); взвешенные (у рёбер есть вес — расстояние, стоимость) и невзвешенные.
Где применяют:
	В социальных сетях (модель связей пользователей).
	В компьютерных и транспортных сетях (маршрутизация, поиск оптимальных путей).
	В компиляторах (анализ зависимостей, потока данных).
	В планировании проектов (топологическая сортировка).
	В машинном обучении (нейронные сети).
Реализация:
	Матрица смежности — двумерный массив, где matrix[i][j] показывает наличие ребра между вершинами i и j. Удобна для плотных графов, но требует много памяти.
	Список смежности — для каждой вершины хранится список смежных вершин. Эффективнее для разреженных графов.
	Список рёбер — просто список всех рёбер с их характеристиками.
Trie (префиксное дерево)
Trie — структура, оптимизированная для работы со строками. Каждый узел представляет один символ, а путь от корня до узла формирует строку. Часто в узле есть флаг endOfWord, отмечающий конец слова.

Где применяют:
	Автодополнение в поисковых системах и текстовых редакторах.
	Проверка орфографии (поиск похожих слов).
	IP-маршрутизация (поиск по префиксу адреса).
	В биоинформатике (поиск подстрок в последовательностях).
Реализация: узел обычно содержит словарь (children) для ссылок на потомков по символам и флаг endOfWord. Операции (вставка, поиск, удаление) сводятся к последовательному проходу по символам строки.
Оптимизации: существуют варианты, экономящие память. Например, radix tree (сжатое префиксное дерево) объединяет узлы с единственным потомком.
Какой вывод?
Выбор структуры зависит от задачи:
	Если нужно хранить отсортированные данные и быстро искать — BST (возможно, самобалансирующееся).
	Если важна приоритетная очередь или сортировка — куча.
	Если моделируете сложные связи (сети, зависимости) — граф.
	Если работаете со строками и часто ищете по префиксу — trie.

3. Модули: heapq, queue, collections, functools — зачем нужны, когда использовать?
модули — часть стандартной библиотеки Python, и каждый решает свою задачу. Я коротко разберу, зачем они нужны и когда их применять.
heapq
Зачем нужен: реализует минимальную кучу (min-heap) — структуру, где корневой элемент всегда наименьший. Это позволяет эффективно работать с приоритетами: быстро получать и удалять минимальный элемент, вставлять новые.
Когда использовать:
	Нужно найти k наименьших или наибольших элементов в наборе данных (есть удобные функции nsmallest() и nlargest()).
	Реализуете приоритетную очередь — например, в планировщике задач, где задачи с высшим приоритетом обрабатываются первыми.
	Работаете с алгоритмами на графах (например, алгоритм Дейкстры).
	Нужно слить несколько отсортированных последовательностей в одну (функция merge()).
Нюанс: по умолчанию куча минимальная. Чтобы эмулировать максимальную (max-heap), можно инвертировать значения (например, хранить -x вместо x). Важно: все операции (добавление, извлечение) должны проходить через функции модуля (heappush, heappop), иначе свойства кучи нарушатся.


queue
Зачем нужен: предоставляет потокобезопасные очереди для обмена данными между потоками (или процессами — через multiprocessing.Queue). Внутри используются блокировки, чтобы избежать гонок данных.
Когда использовать:
	В многопоточных приложениях, где один поток (производитель) добавляет задачи, а другие (потребители) их обрабатывают.
	Когда нужно организовать очередь с определённым порядком: FIFO (обычная очередь), LIFO (стек) или с приоритетом (внутри может использоваться heapq).
Примеры классов: Queue (FIFO), LifoQueue (LIFO), PriorityQueue.
collections
Зачем нужен: расширяет встроенные типы данных (списки, словари, кортежи), предлагая специализированные контейнеры для конкретных сценариев. Это помогает писать более читаемый и эффективный код.
Когда использовать:
	Подсчёт элементов — Counter (подкласс dict для подсчёта вхождений элементов в итерируемом объекте).
	Словарь со значением по умолчанию — defaultdict (автоматически создаёт ключ со значением по умолчанию при обращении к несуществующему ключу, избавляя от проверок if key not in dict).
	Двусторонняя очередь — deque (оптимизирована для быстрого добавления и удаления элементов с обоих концов; полезна в BFS, для реализации скользящего окна).
	Именованные кортежи — namedtuple (создаёт класс с именованными полями — код становится самодокументирующимся).
	Словарь, запоминающий порядок вставки — OrderedDict (в Python 3.7+ обычный dict тоже сохраняет порядок, но OrderedDict даёт дополнительные методы для переупорядочивания).
	Объединение нескольких словарей — ChainMap (удобно для многоуровневых конфигураций: пользовательские настройки поверх настроек проекта).
functools
Зачем нужен: содержит инструменты для работы с функциями высшего порядка — функциями, которые принимают другие функции как аргументы, возвращают функции или и то, и другое. Это помогает делать код более переиспользуемым и выразительным.
Когда использовать:
	Кэширование результатов — декораторы @lru_cache (кэш с ограничением размера) или @cache (неограниченный кэш) для запоминания результатов тяжёлых вычислений.
	Частичное применение функций — partial «замораживает» часть аргументов, создавая новую функцию с упрощённой сигнатурой.
	Автоматическое определение методов сравнения — декоратор @total_ordering (достаточно реализовать __eq__ и один из методов сравнения, остальные сгенерируются автоматически).
	Множественная диспетчеризация — singledispatch и singledispatchmethod для перегрузки функций в зависимости от типа аргументов.
	Обновление метаданных обёртки — update_wrapper (полезно при написании собственных декораторов, чтобы обёртка «выглядела» как оригинальная функция).
	Свёртка итерируемого объекта — функция reduce (последовательно применяет функцию к элементам, сводя их к одному значению).
Короткий чек-лист
	Нужна приоритетная очередь или поиск экстремумов? → heapq.
	Нужно безопасно обмениваться данными между потоками? → queue.
	Нужно оптимизировать работу со структурами данных (подсчёт, двусторонняя очередь, именованные поля)? → collections.
	Нужно сделать код выразительнее (кэшировать, частично применять функции, автоматизировать сравнения)? → functools.

4. Что используется в Python для обозначения пустоты.
В Python для обозначения «пустоты» или отсутствия значения используют несколько вещей — в зависимости от того, что именно нужно выразить.
None — главное обозначение «ничего»
None — это специальный объект типа NoneType, который означает «значение отсутствует», «неизвестно», «не задано». Это аналог null в других языках.
Где применяют:
	как значение по умолчанию для необязательных аргументов:
python
def greet(name=None):
    if name is None:
        return "Привет, незнакомец!"
    return f"Привет, {name}!"
	чтобы показать, что функция ничего не возвращает (или явно вернуть «ничего»):
python
def do_nothing():
    return None  # или вообще без return — результат всё равно None
	для инициализации переменной «пока пусто»:
python
result = None
# позже в коде: result = какое-то_значение
Важно: проверять на None нужно через is / is not, а не через ==:
python
if x is None: ...
if x is not None: ...
Пустые контейнеры — это не «отсутствие значения», а «пустая коллекция»
Пустые структуры данных — это валидные значения, просто в них нет элементов:
	пустой список: []
	пустая строка: ""
	пустой кортеж: ()
	пустой словарь: {}
	пустое множество: set()
Они отличаются от None: [] — это «список, в котором пока ничего нет», а None — это «списка вообще нет / значение не задано».
В булевом контексте они считаются ложными (False):
python
bool([])      # False
bool("")      # False
bool({})      # False
Но это не значит, что они равны None:
python
[] is None    # False
"" is None    # False
Специальные случаи
	Ellipsis (...) — иногда используют как «заглушку» или маркер «будет позже». Чаще встречается в аннотациях типов (Callable[..., int]) или в NumPy для срезов. Это не про «пустоту» в смысле «нет данных», а скорее про «неопределённую часть».
	NotImplemented — специальное значение для операций, которые тип не поддерживает; не для обозначения пустоты.

Практические подсказки
	Если нужно показать «значение не задано» или «результат не найден» — используйте None.
	Если нужна «пустая коллекция, с которой можно сразу работать» (добавлять элементы и т. п.) — берите [], {} и т. д.
	Избегайте использовать изменяемые объекты (вроде []) как значения по умолчанию в функциях:
python
# Плохо: список общий для всех вызовов
def add_item(item, lst=[]):
    lst.append(item)
    return lst
# Хорошо:
def add_item(item, lst=None):
    if lst is None:
        lst = []
    lst.append(item)
    return lst

5. Связь между bool и int в Python.
В Python типы bool и int тесно связаны: bool — это подкласс int. Из за этого True и False ведут себя в числовом контексте как 1 и 0.
Ключевые факты
	True == 1 и False == 0 — это правда по значению.
	При этом типы разные: type(True) — это <class 'bool'>, а type(1) — <class 'int'>.
	Но проверка наследования подтверждает связь: isinstance(True, int) и isinstance(False, int) возвращают True.
Числовое поведение
Благодаря наследованию булевы значения можно использовать в арифметике:
python
True + 2        # 3
False * 5       # 0
10 - True       # 9
3 * (True + False)  # 3
Также можно явно преобразовать:
python
int(True)   # 1
int(False)  # 0
bool(1)     # True
bool(0)     # False
bool(5)     # True (любое ненулевое число — True)
bool(-3)    # True
Где это проявляется на практике
	Подсчёт количества истинных условий:
python
nums = [1, 0, -5, 7, 0]
count_nonzero = sum(bool(x) for x in nums)   # или просто sum(nums) не подойдёт, но:
count_positive = sum(x > 0 for x in nums)    # здесь True считается как 1
Выражение x > 0 даёт True/False, а sum складывает их как 1/0.
	Индексация:
python
ПереноситьСвернутьКопировать
options = ["нет", "да"]
choice = True
print(options[choice])  # "да", потому что True → 1
	Битовые и логические операции:
Побитовые операторы (&, |, ^) работают с числовым представлением, поэтому True & False — это по сути 1 & 0.
Важные нюансы и предостережения
	Не стоит полагаться на эту связь там, где важна семантика. Если функция ожидает число — передайте число, если логическое значение — используйте True/False. Смешивание может запутать читающего код.
	Проверка на равенство vs идентичность:
python
True == 1      # True
False == 0     # True
True is 1      # False (это разные объекты)
	Булево приведение других типов работает по своим правилам, не через «равенство нулю»:
python
bool("")        # False
bool([])        # False
bool("любая непустая строка")  # True
bool([0])       # True (список непустой, даже если элемент — 0)
Пример, где это удобно и где лучше избегать
Удобно:
python
# Сколько элементов удовлетворяют условию?
scores = [85, 92, 78, 60, 95]
above_80 = sum(score > 80 for score in scores)  # 4
Здесь генератор выдаёт True/False, sum трактует их как 1/0 — код лаконичный и понятный.
Лучше избегать:
python
if flag == 1: ...   # плохо: смешивает булеву и числовую семантику
if flag: ...        # хорошо: явно логическое условие

6. Сравнение переменных разных типов: a = 1, b = True, c = 1.0 — равны ли они, почему.
Да, в Python выражения a == b, b == c и a == c для a = 1, b = True, c = 1.0 вернут True. Но это не значит, что переменные одного типа или идентичны.
Что происходит при сравнении
	a == b (1 == True) → True, потому что True — это подкласс int и равен 1.
	b == c (True == 1.0) → True, так как True приводится к 1, а 1 == 1.0 в Python истинно.
	a == c (1 == 1.0) → True: Python считает целое 1 и число с плавающей точкой 1.0 равными по значению.
Это поведение заложено в семантике оператора ==: он сравнивает значения, а не типы, и для чисел учитывает числовую эквивалентность.
Важные различия, которые остаются
	Типы разные:
python
type(a)  # <class 'int'>
type(b)  # <class 'bool'>
type(c)  # <class 'float'>
	Идентичность объектов — нет:
python
a is b  # False
b is c  # False
a is c  # False
Оператор is проверяет, указывают ли переменные на один и тот же объект в памяти — здесь это не так.
	Хеш-значения совпадают для 1 и True:
python
hash(1) == hash(True)  # True
Именно поэтому в множествах и как ключи словаря 1 и True считаются одним ключом:
python
s = {1, True}
len(s)  # 1
Почему так спроектировано
	bool — подкласс int: исторически в ранних версиях Python булевы значения были просто числами 0 и 1. Сейчас True и False — отдельные объекты, но совместимость с арифметикой сохранена.
	Числа разных типов сравниваются по значению: 1 == 1.0 логично считать истинным, ведь это одно и то же число, просто в разных представлениях.
Практический совет
Если важна именно логическая семантика, не смешивайте числа и булевы значения:
python
# Плохо: зависит от числовой интерпретации
if flag == 1:
# Хорошо: явно логическое условие
if flag:
Если нужно проверить и значение, и тип, используйте комбинацию:
python
a == b and type(a) == type(b)
или isinstance с нужными проверками.

7. Отличие tuple и list в плане памяти, как выделяется память под list.
Разница действительно есть, и она напрямую вытекает из главного отличия: кортежи (tuple) неизменяемы (immutable), а списки (list) — изменяемы (mutable). Я объясню, как это влияет на память и как именно Python выделяет её под список.
Чем отличаются в плане памяти
	Кортеж (tuple). После создания его размер фиксирован. Python точно знает, сколько элементов в нём будет, и выделяет ровно столько памяти, сколько нужно для хранения ссылок на все эти элементы. Нет «запаса» на будущее — только то, что есть сейчас. Если вам нужно «добавить» элемент, создаётся новый кортеж, куда копируются все старые элементы плюс новый.
	Список (list). Из-за возможности менять содержимое (добавлять, удалять элементы) Python не может выделить память строго под текущий размер. Чтобы операция добавления (append) не становилась медленной (не приходилось каждый раз перевыделять память и копировать все элементы), используется стратегия over-allocation (перевыделения с запасом). То есть при создании или расширении списка Python резервирует немного больше памяти, чем нужно сейчас. Это позволяет в будущем добавлять элементы без немедленного перевыделения. В результате список обычно занимает чуть больше памяти, чем кортеж с тем же количеством элементов.
Пример для наглядности:
python
import sys
a_tuple = (1, 2, 3)
a_list = [1, 2, 3]
print(sys.getsizeof(a_tuple))  # Например, 48 байт
print(sys.getsizeof(a_list))   # Например, 64 байта
Видно, что список занимает больше. datagy.io +1
Как выделяется память под список
Внутри список устроен примерно как динамический массив. Объект списка состоит из двух частей:
	Заголовок — фиксированная часть, где хранятся служебные данные (например, текущий размер, выделенная ёмкость, ссылка на массив ссылок).
	Массив ссылок — здесь хранятся указатели на объекты, которые являются элементами списка.
Когда вы создаёте список, Python выделяет память под заголовок и под массив ссылок начального размера. При добавлении элементов, если текущий массив заполнен, срабатывает механизм перевыделения:
	Python вычисляет новую, бо́льшую ёмкость (алгоритм роста не всегда удваивает размер — иногда добавляется фиксированное число элементов, в зависимости от текущей длины).
	Выделяется новый, более крупный блок памяти.
	Все существующие элементы копируются из старого массива в новый.
	Старый блок памяти освобождается.
Именно из-за этого «запаса» (разницы между текущим размером и выделенной ёмкостью) список и потребляет больше памяти, чем кортеж с тем же числом элементов.
Когда что выбрать
Из-за этой особенности памяти кортежи стоит использовать, когда у вас есть фиксированный набор данных, который не планируется менять (например, константы, записи из базы данных). Списки — когда вам нужна гибкость: вы заранее не знаете, сколько элементов будет, или планируете их активно добавлять/удалять.

8. Как выделяется память под другие типы данных?
В CPython (стандартной реализации Python) память под объекты выделяется через иерархический аллокатор: арены → пулы → блоки. Для разных типов данных используют разные стратегии — от «заранее заготовленных» маленьких объектов до динамических структур с запасом.
Ниже — как это устроено для основных типов.
Числа (int, float, complex)
	int (целые). В CPython маленькие целые числа (обычно от −5 до 256) кешируются: для них заранее создаются объекты, и при присваивании x = 5 просто берётся уже существующий. Это экономит память и ускоряет работу. Большие числа — полноценные объекты: выделяется блок нужного размера (плюс заголовок объекта), внутри хранится массив «цифр» в базе 2^30(в 64 битной сборке). Размер растёт пропорционально количеству разрядов.
	float (C double). Это фиксированный размер: заголовок объекта + 8 байт под значение. Никаких «динамических частей» нет, поэтому sys.getsizeof(3.14) всегда примерно одинаковый.
	complex. Аналогично: заголовок + два double (вещественная и мнимая части).
Строки (str) и байты (bytes)
Строка — это объект с заголовком и массивом символов. Важные моменты:
	Кодировка внутри. CPython хранит строки как Unicode; внутреннее представление зависит от максимальной кодовой точки: ASCII только строки занимают 1 байт на символ, «Latin 1» — 1 байт, BMP — 2 байта, полный Unicode — 4 байта на символ.
	Длина и буфер. В объекте хранится длина и указатель на буфер. Буфер выделяется ровно под длину строки плюс, возможно, небольшой запас (зависит от версии и деталей реализации).
	Оптимизации. Пустые строки и некоторые короткие часто интернируются (переиспользуются). Конкатенация через + в цикле неэффективна: каждый раз создаётся новая строка и копируются данные. Лучше использовать ''.join(list_of_strings).



Коллекции: list, tuple, dict, set
	list. Как уже обсуждали: заголовок + массив указателей на элементы. При росте списка применяется over allocation: выделяется больше ячеек, чем нужно сейчас, чтобы амортизировать стоимость частых append.
	tuple. Неизменяемый, поэтому выделяется ровно столько памяти, сколько нужно для текущего количества элементов. Нет запаса под рост.
	dict. В современных версиях CPython словари используют компактную схему: массив индексов (пробегает по порядку вставки) и массив записей (ключ, хеш, значение). Это даёт экономию памяти и сохраняет порядок вставки. Хеш таблицы часто имеют «запас» (load factor), чтобы не деградировать производительность при коллизиях.
	set. Похож на dict, но без значений: хранятся только ключи. Использует ту же стратегию хеш таблицы.

Пользовательские классы: обычные и __slots__
	Обычный класс. Экземпляр имеет __dict__ — это словарь, где хранятся атрибуты. Плюс служебные поля. Это удобно, но каждый экземпляр несёт накладные расходы на словарь.
	__slots__. Если в классе объявить __slots__ = ['x', 'y'], Python не создаёт __dict__, а выделяет фиксированный набор полей. Это сильно экономит память на большом количестве объектов и немного ускоряет доступ к атрибутам.
Пример:
python
class A:
    def __init__(self, x, y):
        self.x = x
        self.y = y

class B:
    __slots__ = ('x', 'y')
    def __init__(self, x, y):
        self.x = x
        self.y = y
Экземпляры B занимают заметно меньше памяти, чем A.
Иерархия аллокации в CPython
Для объектов размером до ~256 байт используется специальный аллокатор малых объектов:
	Арена (arena) — большой кусок памяти (обычно 256 КБ), который ОС отдаёт интерпретатору.
	Пул (pool) — блок 4 КБ внутри арены, разбитый на блоки одинакового размера.
	Блок (block) — ячейка фиксированного размера (кратна 16 байтам, до 512 байт), в которой живёт один объект.
Объекты большего размера (например, очень большие списки или строки) выделяются через системный аллокатор (аналог malloc).
Такая схема позволяет быстро выделять и освобождать много мелких объектов и эффективно использовать кэш процессора.
Как посмотреть размер
Используйте sys.getsizeof() для «поверхностного» размера объекта (сам объект, но не содержимое контейнеров):
python
import sys
a = 1
b = [1, 2, 3]
c = "hello"
print(sys.getsizeof(a))  # размер int
print(sys.getsizeof(b))  # размер списка (не включая сами элементы)
print(sys.getsizeof(c))  # размер строки
Чтобы оценить «полный» размер структуры (включая вложенные объекты), используют сторонние инструменты вроде pympler.asizeof.

Практические следствия
	Неизменяемые типы (int, str, tuple) можно безопасно «переиспользовать»: CPython часто возвращает один и тот же объект для одинаковых значений.
	Изменяемые типы (list, dict) требуют отдельного блока и могут иметь «запас», чтобы быстро расти.
	Малое количество больших объектов и много маленьких объектов — это разные сценарии: в первом случае важна длина буферов, во втором — эффективность аллокатора малых блоков и отсутствие лишних словарей (__slots__, кортежи вместо словарей и т. п.).

9. Можно ли использовать в качестве ключа в словаре tuple с list внутри? Почему?
Нет, нельзя использовать в качестве ключа в словаре кортеж, внутри которого есть список.
Что будет на практике
python
d = {}
key = (1, [2, 3])
d[key] = "значение"
# TypeError: unhashable type: 'list'
Ошибка возникает сразу при попытке использовать такой кортеж как ключ.
Почему так
Ключом в словаре может быть только хешируемый объект. У него должен быть стабильный __hash__, который не меняется со временем, и корректное сравнение через __eq__.
	Кортеж сам по себе хешируем, если все его элементы тоже хешируемы.
	Список — нехешируемый тип: у него нет осмысленного __hash__ именно потому, что он изменяемый.
Поэтому (1, [2, 3]) не считается хешируемым: наличие внутри списка «портит» хешируемость всего кортежа.
В чём проблема с изменяемыми объектами в ключах
Допустим, мы каким то образом смогли бы использовать список (или кортеж со списком) как ключ и положить его в словарь. Потом мы меняем содержимое списка:
python
key = (1, [2, 3])
d[key] = "значение"
key[1].append(4)  # теперь ключ фактически стал (1, [2, 3, 4])
Что происходит с хеш значением? Оно должно зависеть от содержимого, то есть измениться. Но словарь уже положил эту пару «ключ–значение» в какой то «бакет» (ячейку хеш таблицы) на основе старого хеша. После изменения хеша ключ оказывается «не там», где его будет искать словарь. В результате:
	поиск по ключу может не найти значение, хотя логически оно должно быть;
	могут появляться странные ошибки и несоответствия;
	поведение становится непредсказуемым.
Именно поэтому Python запрещает использовать нехешируемые типы (и любые структуры, содержащие их) в качестве ключей.
Что можно сделать вместо этого
Если вам нужно «закодировать» набор данных, включающий изменяемые части, в ключ, используйте варианты с полностью неизменяемыми структурами:
	Заменить список на кортеж:
python
key = (1, (2, 3))  # хешируемый
d[key] = "значение"
	Преобразовать список в строку (например, через repr или json.dumps), но это уже семантически другой тип ключа:
python
import json
key = (1, json.dumps([2, 3]))  # строка неизменяема, хешируема
d[key] = "значение"
	Вычислить хеш вручную и использовать его как ключ (если нужна именно контрольная сумма содержимого), но тогда ключом будет число или строка с хешем, а не исходная структура.
Важное уточнение про «неизменяемость» кортежей
Кортеж считается неизменяемым, но это не значит, что всё внутри него тоже неизменно. Кортеж может содержать ссылки на изменяемые объекты (списки, словари и т. п.) — он просто не позволит заменить сами элементы кортежа, но не помешает менять содержимое этих объектов. Именно поэтому наличие изменяемого элемента делает кортеж нехешируемым, даже если формально вы не можете «переприсвоить» элемент кортежа.
Если скажете, какую задачу вы пытаетесь решить (например, «хочу группировать данные по комбинации ID и набора тегов»), подскажу самый подходящий вариант структуры для ключа.

10. Коллизии в hash table (словаре), методы борьбы (и как это реализовано в Python).
Что такое коллизия в хеш таблице
Коллизия — это ситуация, когда два разных ключа дают одинаковый хеш (индекс в массиве). Поскольку количество возможных ключей обычно намного больше числа ячеек таблицы, коллизии неизбежны.
Пример:
python
hash("abc") % 8 == 3
hash("xyz") % 8 == 3   # коллизия
Основные методы борьбы с коллизиями
	Цепочки (separate chaining). В каждой ячейке хранится список (или другая структура) всех ключей с одинаковым хешем. Поиск внутри ячейки — линейный.
	Открытая адресация (open addressing). При коллизии ищут другую свободную ячейку по определённому правилу (линейное пробирование, квадратичное, двойное хеширование).
	Перехеширование и изменение размера таблицы. Когда таблица становится слишком плотной (высокий load factor), её размер увеличивают и все элементы перераспределяют по новым индексам.
Как это реализовано в Python (CPython)
В современных версиях CPython (начиная с 3.6+ для компактного представления, стабильно с 3.7+) словари используют открытую адресацию со специальной схемой, которая одновременно экономит память и сохраняет порядок вставки.
Структура словаря в CPython
Есть два массива:
	Индексы (indices) — массив байт/целых, который хранит «позиции» записей. Он разреженный: большинство ячеек — пустые.
	Записи (entries) — плотный массив, где хранятся тройки (hash, key, value) в порядке вставки.
Когда вставляется новый ключ:
	Вычисляется h = hash(key).
	По этому хешу и размеру массива индексов определяется начальная позиция.
	Если ячейка занята и ключи не совпадают — это коллизия, и алгоритм переходит к следующей ячейке по правилу пробирования.
	Как только найдена свободная ячейка в indices, в конец массива entries добавляется новая запись, а в indices пишется её позиция.
Такой подход даёт:
	Компактность: массив записей не содержит «дыр», а разреженность только в индексах.
	Сохранение порядка: записи добавляются в entries последовательно.
	Быстрый перебор: итерация идёт по плотному массиву записей.
Пробирование при коллизиях
CPython использует псевдослучайное (перемешанное) пробирование, а не простое линейное. Формула примерно такая:
next_index = (current_index + perturb) % table_size,
где perturb уменьшается на каждом шаге по специальной формуле, зависящей от битов хеша.
Это помогает избежать кластеризации (когда коллизии образуют длинные цепочки занятых ячеек) и делает распределение более равномерным.
Борьба с переполнением: рост таблицы
Ключевой параметр — load factor (доля занятых ячеек). В CPython словарь начинает расти, когда заполненность превышает примерно ⅔. Тогда:
	Создаётся новая таблица большего размера (обычно примерно в 2 раза).
	Все существующие ключи заново хешируются и размещаются в новой таблице.
	Старую таблицу удаляют.
Рост таблицы амортизирует стоимость вставок: хотя иногда происходит дорогая операция перестройки, в среднем вставка остаётся O(1).
Хеширование ключей и защита от атак
	Ключи должны быть хешируемыми (__hash__ и __eq__).
	Хеш вычисляется один раз при вставке и сохраняется вместе с ключом в записи. Это ускоряет повторные операции.
	Для строк и некоторых других типов используется рандомизация хеша (seed выбирается при старте интерпретатора). Это защищает от DoS атак, основанных на создании большого числа коллизий.
Практические следствия для разработчика
	Сложность операций: в среднем O(1) для вставки, поиска и удаления; в худшем случае (много коллизий из за плохого хеша) — до O(n), но на практике это редкость.
	Порядок ключей: гарантируется начиная с Python 3.7 (за счёт отдельного массива записей).
	Нехешируемые ключи (например, списки, словари) нельзя использовать: у них нет стабильного хеша, и это сломало бы всю логику хеш таблицы.

Пример, где коллизии «видны» косвенно
python
ПереноситьСвернутьКопировать
d = {}
for i in range(100_000):
    d[i] = i
# При достижении порога заполненности произойдёт ресайз (перестройка таблицы)
Вы не видите коллизии напрямую, но именно из за них и нужен механизм пробирования и роста таблицы.

11. Какие есть методы разрешения коллизий?
Основные методы разрешения коллизий в хеш таблицах делятся на две большие группы: с цепочками и с открытой адресацией. Плюс отдельно стоит упомянуть вспомогательные стратегии (изменение размера, улучшение хеширования).
Метод цепочек (Separate Chaining)
Идея: в каждой ячейке таблицы хранится не один элемент, а контейнер (обычно связный список, иногда сбалансированное дерево) со всеми ключами, попавшими в эту ячейку по хешу.
Как работает:
	Вычисляем index = hash(key) % size.
	Идём в ячейку table[index] и ищем нужный ключ в её списке.
	При вставке добавляем элемент в список (часто в начало — это O(1)).
Плюсы:
	Простота реализации.
	Хорошо работает даже при высоком коэффициенте заполнения (load factor).
	Удаление и вставка достаточно просты.
Минусы:
	Дополнительная память под указатели/структуры списков.
	При длинных цепочках поиск деградирует до O(n).
Где встречается: Java (HashMap до Java 8, потом для длинных цепочек используют красно чёрное дерево), многие учебные реализации.
Открытая адресация (Open Addressing)
Здесь в таблице хранятся сами элементы, а при коллизии ищут другую свободную ячейку по заранее заданному правилу.
Линейное пробирование (Linear Probing)
Правило: если ячейка h занята, проверяем h+1, h+2, … (по модулю размера таблицы).
	Плюс: очень простая логика и хорошая локальность данных (ячейки рядом).
	Минус: быстро образуются «кластеры» занятых ячеек, из за чего производительность падает.
Квадратичное пробирование (Quadratic Probing)
Правило: шаги растут квадратично: h, h+1, h+4, h+9, …
	Плюс: уменьшает первичную кластеризацию.
	Минус: может не найти свободную ячейку даже при наличии пустых мест (проблема цикличности), и возможна вторичная кластеризация.
Двойное хеширование (Double Hashing)
Правило: используют вторую хеш функцию h2(key) и делают шаги h1 + i*h2 (по модулю).
	Плюс: распределение намного равномернее, почти нет кластеризации.
	Минус: нужно вычислять две хеш функции; чуть сложнее реализация.
Псевдослучайное (перемешанное) пробирование
Используют специальную последовательность шагов, зависящую от битов хеша (именно так сделано в CPython). Это компромисс между простотой и равномерностью.
Плюсы открытой адресации:
	Нет накладных расходов на указатели (меньше памяти).
	Хорошая работа с кэшем процессора (данные плотнее).
Минусы:
	Производительность сильно зависит от load factor: таблицу нужно чаще увеличивать.
	Удаление сложнее: нельзя просто очистить ячейку, иначе разорвётся цепочка поиска; используют «удалённые» метки (tombstones) или перестройку.
Вспомогательные стратегии (не заменяют, а дополняют методы)
	Изменение размера таблицы (Resize / Rehash). Когда load factor становится слишком большим (например, > 2/3), таблицу увеличивают (часто ×2) и перераспределяют все элементы. Это амортизирует стоимость дорогих операций.
	Улучшение хеш функции. Равномерное распределение хешей сильно снижает число коллизий.
	Рандомизация хеша (salt/seed). В Python seed выбирается при старте, чтобы злоумышленник не мог специально создать много коллизий и замедлить работу словаря.
Как это реализовано в Python (CPython)
В Python словари используют открытую адресацию со специальной схемой:
	Два массива: компактный массив записей (hash, key, value) (в порядке вставки) и разреженный массив индексов.
	При коллизии используется псевдослучайное пробирование: шаг зависит от битов хеша и уменьшается по специальной формуле. Это уменьшает кластеризацию.
	Таблица растёт, когда заполненность становится слишком высокой; все элементы перехешируются в новую, большую таблицу.
	Хеш ключа сохраняется вместе с записью, чтобы не пересчитывать его каждый раз.
	Для строк и некоторых типов хеш рандомизирован (seed при старте), чтобы усложнить DoS атаки через массовые коллизии.
Другие подходы (менее распространённые в обычных словарях)
	Cuckoo Hashing. Ключ может находиться в одном из нескольких мест (по разным хеш функциям). При коллизии «выталкивают» существующий ключ в его альтернативное место. Даёт почти гарантированный O(1), но требует аккуратной обработки циклов и перестройки.
	Coalesced Hashing. Гибрид цепочек и открытой адресации: часть ячеек хранят указатели на продолжение цепочки.

12. Вставка большого количества элементов в list: что происходит с памятью и производительностью.
При вставке большого количества элементов в list в Python происходят два взаимосвязанных процесса: управление памятью (выделение и перераспределение) и влияние на производительность (время выполнения).
Что происходит с памятью
Список в CPython — это динамический массив указателей на объекты. Внутри него есть:
	Текущая длина (size) — сколько элементов реально хранится.
	Ёмкость (allocated capacity) — сколько ячеек зарезервировано под элементы.
Чтобы частые вставки были быстрыми, используется over-allocation (перевыделение с запасом): ёмкость делают больше текущей длины.
Механизм роста ёмкости
Когда вы делаете append, а массив заполнен, CPython выделяет новый массив большей ёмкости и копирует туда старые указатели. Формула роста не линейная и не строго удвоение: она устроена так, чтобы амортизировать редкие, но дорогие операции копирования.
Упрощённо поведение такое:
	При малом размере ёмкость растёт заметно.
	При большом размере добавляется «запас» примерно на 12,5–25 % от текущего размера (точная формула зависит от реализации и версии CPython).
В результате:
	Список занимает больше памяти, чем строго необходимо для хранения текущих элементов.
	Этот «запас» нужен, чтобы не делать перераспределение при каждой вставке.
	Если вы вставляете миллион элементов по одному через append, итоговая ёмкость может быть, например, на 10–20 % больше миллиона — это нормально и задумано специально.
Производительность: амортизированная сложность O(1)
Отдельная операция list.append(x) в среднем работает за амортизированное O(1). Это значит:
	В большинстве случаев — очень быстро (просто записать указатель в следующую ячейку).
	Иногда (когда массив полон) происходит дорогое перевыделение и копирование всех элементов — это O(n) для текущего размера.
Но поскольку такие «дорогие» операции случаются редко (по мере роста списка они становятся всё реже относительно числа вставок), среднее время на одну вставку остаётся константным.
Пример:
python
lst = []
for i in range(1_000_000):
    lst.append(i)
Несмотря на миллион итераций, это выполняется быстро именно благодаря амортизированному подходу.
Важные нюансы
	Копирование указателей, а не объектов. При росте списка копируются только указатели (адреса объектов), сами объекты не дублируются. Это дёшево по памяти и времени.
	Фрагментация и кэш. Поскольку список — это непрерывный массив указателей, он хорошо ложится в кэш процессора, что ускоряет последовательный доступ и итерации.
	Пики нагрузки. В моменты перевыделения ёмкости возможны кратковременные всплески времени выполнения и потребления памяти. Для высоконагруженных или жёстко-регламентированных по времени систем это может быть важно.

Вставка не в конец, а по индексу: insert(i, x)
Если вставлять элементы не в конец, а в середину или начало списка (например, lst.insert(0, x) или в случайную позицию), картина резко меняется:
	Чтобы освободить место, нужно сдвинуть часть элементов вправо.
	Это операция O(n) для каждой вставки.
	Если делать так миллион раз, общая сложность будет O(n²) — это очень медленно.
Пример плохой по производительности конструкции:
python
lst = []
for i in range(100_000):
    lst.insert(0, i)   # каждый раз сдвигаются все существующие элементы
Как посмотреть, сколько реально выделено памяти
Точного «capacity» в публичном API нет, но можно оценить потребление памяти:
python
ПереноситьСвернутьКопировать
import sys

lst = []
for i in range(100000):
    lst.append(i)

print(sys.getsizeof(lst))          # размер самого объекта списка (массив указателей + заголовок)
# Обратите внимание: это не включает память под сами элементы (объекты int и т.п.)
sys.getsizeof покажет размер структуры списка, но не учтёт память, занятую объектами, на которые он ссылается.

Практические советы для вставки большого количества элементов
	Используйте append в цикле или extend для готовых коллекций. extend эффективнее, чем миллион отдельных append, потому что он делает одно копирование блока указателей.
python
lst.extend(range(1_000_000))
	Если заранее известен размер, можно заранее подготовить список, хотя в Python нет прямого «reserve», но можно создать список нужной длины и заполнять по индексам:
python
n = 1_000_000
lst = [None] * n
for i in range(n):
    lst[i] = i
Это избегает перевыделений и может быть чуть эффективнее.
	Избегайте частых insert в начало или середину. Если нужна такая операция, рассмотрите collections.deque (двусторонняя очередь) — она оптимизирована для добавления/удаления с обоих концов.
	Для очень больших данных иногда лучше использовать специализированные структуры: массивы из array или numpy.array, если элементы одного типа и важна плотность хранения.

13. Отличие методов extend() и insert() у list.
Главные отличия extend() и insert() у списка в Python
Характеристика	extend(iterable)	insert(index, element)
Что добавляет	Все элементы из итерируемого объекта (список, кортеж, строка и т.п.) по отдельности	Один элемент целиком (неважно, что это — число, список, словарь)
Куда добавляет	Только в конец списка	На указанную позицию (индекс)
Аргумент	Один аргумент — итерируемый объект	Два аргумента: индекс и элемент
Поведение со вложенностью	Распаковывает итерируемый объект: [1].extend([2, 3]) → [1, 2, 3]	Не распаковывает: [1].insert(0, [2, 3]) → [[2, 3], 1]
Сложность	O(k), где k — количество добавляемых элементов	O(n), потому что нужно сдвинуть элементы справа от позиции вставки
Изменяет список	Да (in-place)	Да (in-place)
________________________________________
Примеры
extend()
python
lst = [1, 2]
lst.extend([3, 4, 5])
print(lst)  # [1, 2, 3, 4, 5]

lst.extend("ab")
print(lst)  # [1, 2, 3, 4, 5, 'a', 'b']  # строка — итерируема, добавляются символы

lst.extend((6, 7))
print(lst)  # [1, 2, 3, 4, 5, 'a', 'b', 6, 7]
insert()
python
lst = [1, 2, 3]
lst.insert(1, 99)
print(lst)  # [1, 99, 2, 3]  # вставили 99 на позицию 1

lst.insert(0, [4, 5])
print(lst)  # [[4, 5], 1, 99, 2, 3]  # список добавлен как один элемент

lst.insert(100, "x")  # индекс больше длины — добавит в конец
print(lst)  # [[4, 5], 1, 99, 2, 3, 'x']

Важные нюансы
	С insert() нужно быть осторожным при частых вставках в начало или середину списка. Каждая такая вставка требует сдвига всех последующих элементов, и при большом количестве вставок сложность становится квадратичной: миллион вставок в начало — это примерно O(n²).
	extend() эффективнее, чем цикл с append(). Если нужно добавить много элементов, extend делает это за один проход по итерируемому объекту и лучше оптимизирован внутри CPython.
	Неитерируемые объекты нельзя передавать в extend(). Например, lst.extend(5) вызовет TypeError. Для одного элемента используйте append() или insert().

Когда что выбирать
	Нужен пакет элементов в конец списка (например, объединить два списка) → extend().
	Нужно вставить один элемент в конкретное место (сортировка, поддержание порядка, вставка по условию) → insert().
	Добавляете один элемент в конец → лучше append(), а не insert(len(lst), x): это понятнее и чуть быстрее.

14. Что такое утиная типизация (duck typing) и как это связано с Python.
Что такое утиная типизация
Утиная типизация (duck typing) — это подход, при котором пригодность объекта определяется не по его типу («кто ты?»), а по набору доступных операций («что ты умеешь делать?»).
Название идёт от «утиного теста»: «Если что то выглядит как утка, плавает как утка и крякает как утка — значит, это утка». В программировании это значит: если объект поддерживает нужные методы и поведение, он подходит для задачи, даже если формально не относится к ожидаемому классу.

Как это работает в Python
Python — язык с динамической типизацией, и утиная типизация в нём — основной стиль написания гибкого кода. Интерпретатор не проверяет заранее, принадлежит ли объект нужному классу; он просто пытается вызвать у него требуемый метод. Если метод есть — всё работает, если нет — получаем ошибку в рантайме (AttributeError).
Простой пример
python
class Duck:
    def quack(self):
        return "Кря-кря!"

class RobotDuck:
    def quack(self):
        return "Бип-бип… Кря!"

def make_sound(animal):
    print(animal.quack())

make_sound(Duck())          # Кря-кря!
make_sound(RobotDuck())     # Бип-бип… Кря!
Функция make_sound ничего не знает про классы Duck и RobotDuck. Ей важно только одно: у переданного объекта должен быть метод quack(). Это и есть утиная типизация.
Связь с полиморфизмом и идиоматикой Python
Утиная типизация — это форма полиморфизма без наследования. Объекты не обязаны иметь общего родителя или реализовывать какой то интерфейс. Их объединяет только наличие одинаковых методов с нужной семантикой.
Это очень «питонично»: вместо жёстких проверок типа пишут код, ориентированный на поведение. Сравните два подхода:
Непитоничный (проверка типа):
python
def process(obj):
    if isinstance(obj, MyList):
        ...
Питоничный (утиная типизация):
python
ПереноситьСвернутьКопировать
def process(obj):
    # просто используем интерфейс: итерируемость, индексацию и т.п.
    for x in obj:
        ...
Если объект ведёт себя как коллекция (поддерживает итерацию), он подойдёт, независимо от того, список это, кортеж, генератор или кастомный класс.

Примеры из стандартной библиотеки
	Итерируемость. Многие функции работают с любым итерируемым объектом:
python
list("abc")           # строка
list([1, 2, 3])       # список
list(range(3))       # range
Им не важно, какой тип: важно, что у объекта есть протокол итерации (__iter__ или __getitem__).
	Контекстные менеджеры. with работает с любым объектом, у которого есть __enter__ и __exit__, даже если он не наследуется от какого то базового класса.
	«Протоколы» поведения. Например, для арифметики достаточно реализовать __add__, чтобы объект можно было складывать с помощью +.

Плюсы утиной типизации в Python
	Гибкость. Можно легко подставлять разные реализации, не меняя сигнатуры функций.
	Меньше зависимостей. Не нужно создавать общие базовые классы или интерфейсы.
	Естественность для скриптов и утилит. Быстро писать код, который «просто работает» с разными типами.

Минусы и риски
	Ошибки в рантайме. Если забыть нужный метод, ошибка появится только при выполнении.
	Сложность понимания. По сигнатуре функции не всегда ясно, какие именно методы ожидаются от аргумента.
	Хрупкость при рефакторинге. Изменение API у одного класса может сломать код в другом месте, где этот класс используется «по поведению».

Как сочетать утиную типизацию с надёжностью
В современном Python есть инструменты, чтобы сохранить гибкость утиной типизации и добавить статическую проверку:
	typing.Protocol — описывает «структурный интерфейс»: объект подходит, если у него есть нужные методы, даже без наследования.
python
from typing import Protocol

class Quackable(Protocol):
    def quack(self) -> str: ...

def make_sound(animal: Quackable) -> None:
    print(animal.quack())
Такой код можно проверять статическими анализаторами (mypy, pyright) и получать ошибки до запуска.
	Абстрактные базовые классы (abc.ABC) — если хочется явно объявить контракт и гарантировать реализацию методов.
	Документирование ожиданий. В docstring или типах указывать, какое поведение ожидается (например, «аргумент должен быть итерируемым»).
Практический совет
Пишите функции так, чтобы они опирались на поведение, а не на тип:
	Ожидайте итерируемость вместо «списка».
	Ожидайте поддержку индексации вместо «кортежа».
	Не делайте isinstance там, где достаточно просто вызвать нужный метод.
А если нужна дополнительная надёжность — добавьте Protocol для статической проверки или тесты, которые убедятся, что все реализации ведут себя корректно.

15. Области видимости (LEGB), пространства имен.
Пространства имён в Python
Пространство имён (namespace) — это механизм, который связывает имена (идентификаторы) с объектами. Проще всего представить его как словарь: {'имя': объект}. В Python разные пространства изолированы друг от друга, чтобы одинаковые имена в разных частях программы не конфликтовали.
Основные виды пространств имён:
	Локальное (Local) — создаётся для каждой функции, содержит локальные переменные. Уничтожается после завершения функции.
	Охватывающее (Enclosing) — для вложенных функций: это локальные переменные внешней функции, видимые во внутренней.
	Глобальное (Global) — на уровне модуля (файла). Содержит имена, объявленные вне функций и классов. Живёт всё время работы модуля.
	Встроенное (Built-in) — содержит имена, доступные всегда: len, print, Exception, range и т. д.
Правило LEGB: порядок поиска имён
Когда Python встречает имя (например, x), он ищет его в таком порядке:
	L — Local: сначала в локальной области (внутри текущей функции).
	E — Enclosing: если не найдено, смотрит в охватывающих функциях (для вложенных).
	G — Global: затем в глобальной области модуля.
	B — Built-in: в самом конце — во встроенных именах.
Как только имя найдено, поиск останавливается. Если нигде не найдено — возникает NameError.
Пример с LEGB
python
ПереноситьСвернутьКопировать
x = "глобальный"          # G

def outer():
    x = "охватывающий"     # E

    def inner():
        x = "локальный"    # L
        print(x)           # найдёт в L

    inner()
    print(x)               # найдёт в E

outer()
print(x)                   # найдёт в G
Если в inner() убрать x = "локальный", Python пойдёт дальше по LEGB и найдёт x из outer() (область E). Если убрать и там — возьмёт глобальный x.
Как работают ключевые слова global и nonlocal
Они нужны, чтобы явно указать, какую область видимости мы хотим менять.
global — работа с глобальной переменной
python
count = 0

def increment():
    global count
    count += 1

increment()
print(count)  # 1
Без global count строка count += 1 создаст локальную переменную, а попытка прочитать её до присваивания вызовет UnboundLocalError.
Важное правило: если внутри функции есть присваивание имени (даже count += 1), Python считает это имя локальным для всей функции, если не указано иное (global или nonlocal).

nonlocal — работа с охватывающей областью
Работает только во вложенных функциях и позволяет менять переменную из внешней (но не глобальной) области:
python
def outer():
    total = 0

    def inner(x):
        nonlocal total
        total += x

    inner(5)
    inner(10)
    print(total)  # 15

outer()
Без nonlocal total Python снова решит, что total — локальная переменная внутри inner, и при попытке total += x возникнет ошибка.

Практические примеры и частые ошибки
Затенение (shadowing) имён
python
len = 10

def f():
    print(len)   # выведет 10 (глобальное), потому что в L нет len

f()
# print(len([1, 2, 3]))  # ошибка: len теперь число, а не функция
Здесь мы «затеняем» встроенную функцию len глобальной переменной. Это плохая практика: теряется доступ к built-in версии.
Чтение vs изменение
python
data = [1, 2, 3]

def modify():
    data.append(4)      # OK: мы меняем содержимое списка, а не имя data
    # data = [5, 6]      # это уже создаст локальную data и вызовет проблемы

modify()
print(data)  # [1, 2, 3, 4]
Присваивание data = ... делает data локальной переменной. Простое изменение объекта (например, .append) не требует global.
Полезные функции для работы с пространствами имён
	globals() — возвращает словарь глобального пространства имён.
	locals() — возвращает словарь локального пространства имён (в функции).
	vars(obj) — возвращает __dict__ объекта; без аргумента ведёт себя как locals().
Пример:
python
x = 10

def show():
    y = 20
    print("locals:", locals())
    print("globals:", globals())

show()
Пространства имён вне функций: модули и классы
	Модуль — своё глобальное пространство имён: module_name.variable, module_name.function.
	Класс — пространство имён класса (атрибуты и методы).
	Экземпляр — его собственное пространство имён (__dict__), плюс атрибуты класса.
Это помогает избегать конфликтов: например, math.sin и numpy.sin — это разные имена в разных пространствах.
Связь с утиной типизацией и дизайном кода
Хотя LEGB про поиск имён, а утиная типизация — про поведение объектов, они дополняют друг друга:
	Благодаря LEGB функции могут использовать любые объекты, у которых есть нужные методы, не проверяя их тип.
	Пространства имён позволяют держать такие «утиные» реализации отдельно (разные модули, классы), чтобы не было конфликтов имён.
Частые подводные камни
	Присваивание делает имя локальным. Даже если вы только в конце функции делаете x = 5, Python считает x локальным с самого начала тела функции.
	Не используйте имена встроенных функций (list, str, max, min, sum и т. д.) для своих переменных.
	nonlocal нельзя использовать для глобальных переменных. Для них только global.
	Циклы и условия не создают новых областей видимости. Переменные из for и if видны после блока.

16. Как работает интерпретатор Python (от .py до байткода).
Общий путь: от .py до выполнения
	Инициализация интерпретатора (загрузка рантайма, настройка GIL, модулей и т. д.).
	Чтение исходного файла .py.
	Лексический анализ (токенизация) — разбиение текста на токены (ключевые слова, идентификаторы, операторы, литералы).
	Синтаксический анализ (парсинг) — построение абстрактного синтаксического дерева (AST) по правилам грамматики Python.
	Компиляция AST в байткод — генерация последовательности инструкций для виртуальной машины Python (PVM).
	Исполнение байткода на PVM (цикл выборки-исполнения инструкций).
	Управление памятью и сборкой мусора во время выполнения.
Важно: хотя Python называют «интерпретируемым», в CPython это скорее интерпретатор байткода. Сначала код компилируется в байткод (не в машинный код), а потом байткод исполняется.
Детали этапов
Токенизация и парсинг
	Токенизатор читает текст и выдаёт поток токенов. Например, x = 1 + 2 превратится в токены: NAME(x), ASSIGN, NUMBER(1), PLUS, NUMBER(2).
	Парсер строит AST, игнорируя лишние пробелы и комментарии. AST — это дерево, где узлы соответствуют конструкциям языка (присваивания, вызовы функций, циклы и т. п.).
Компиляция AST в байткод
Компилятор Python преобразует AST в инструкции виртуальной машины. Каждая инструкция имеет:
	Opcode (код операции),
	Аргумент (если нужен, например, индекс в константах или имя в глобальном пространстве).
Пример: для кода
python
x = 10
y = x + 5
может получиться примерно такой байткод (упрощённо):
	LOAD_CONST(10), STORE_NAME(x)
	LOAD_NAME(x), LOAD_CONST(5), BINARY_ADD, STORE_NAME(y)
Байткод хранится в объекте кода (code object). В нём есть:
	Массив инструкций,
	Константы (co_consts),
	Имена глобальных переменных (co_names),
	Локальные имена (co_varnames),
	Флаги (например, есть ли генераторы, аннотации и т. п.),
	Таблица номеров строк (для отладки и трейсов).
Виртуальная машина Python (PVM)
PVM — это главный цикл интерпретатора, который:
	Берёт текущую инструкцию.
	Выполняет её (часто через большой switch по opcode на C).
	Обновляет стек операндов и состояние кадра (frame).
	Переходит к следующей инструкции (адрес следующей может меняться, например, при переходах).
Ключевые детали:
	Стек операндов: большинство операций работают со стеком. Например, LOAD_CONST кладёт значение на стек, BINARY_ADD снимает два значения, складывает и кладёт результат обратно.
	Кадры (frames): каждый вызов функции создаёт новый кадр, где хранятся локальные переменные, стек операндов, указатель на инструкцию и т. д.
	Управление потоком: переходы (JUMP_FORWARD, POP_JUMP_IF_FALSE и др.) меняют указатель инструкции.

Файлы .pyc и кэширование байткода
Когда вы запускаете модуль, CPython (если есть права на запись) сохраняет скомпилированный байткод в файле .pyc в директории __pycache__. В .pyc хранится:
	Заголовок с меткой версии Python,
	Сериализованный объект кода (байткод + метаданные).
При следующем запуске, если исходный .py не изменился, интерпретатор загружает .pyc напрямую, минуя токенизацию, парсинг и компиляцию AST. Это ускоряет старт.

Что именно компилируется
Компилируется не весь файл как одна единица, а единицы компиляции: модули, функции, классы, генераторы, корутины. Для каждой такой единицы создаётся свой объект кода. Например:
	Модуль → объект кода модуля.
	Функция → отдельный объект кода, вложенный в модуль.
	Внутри функции могут быть объекты кода для вложенных функций, генераторов и т. п.
Именно поэтому байткод функции может ссылаться на константы и имена, определённые в её замыкании или в глобальной области.

Практический пример: посмотреть байткод
python
import dis

def f(x):
    return x + 1

dis.dis(f)
Вывод покажет инструкции вроде:
	LOAD_FAST (локальная переменная),
	LOAD_CONST,
	BINARY_ADD,
	RETURN_VALUE.
Это и есть тот самый байткод, который будет исполнять PVM.
________________________________________
Важные нюансы
	Байткод платформонезависим, но версия байткода привязана к версии CPython. .pyc от Python 3.11 не запустится в 3.10.
	Не машинный код: байткод не является инструкциями процессора. Он исполняется интерпретатором на C.
	Оптимизации ограничены: в CPython почти нет агрессивной оптимизации кода. Некоторые простые вещи (например, сворачивание констант) всё же делаются на этапе компиляции.
	Другие реализации: PyPy использует JIT и может транслировать части байткода в машинный код на лету; Jython компилирует в байткод JVM; IronPython — в .NET IL.
________________________________________
Как это связано с тем, что мы обсуждали раньше
	LEGB и пространства имён: при исполнении байткода PVM обращается к разным пространствам имён (глобальные, локальные, встроенные) через инструкции LOAD_NAME, LOAD_GLOBAL, LOAD_FAST, LOAD_DEREF и т. п. Выбор инструкции зависит от области видимости переменной.
	Утиная типизация: PVM не проверяет типы объектов. Он просто вызывает методы/операции. Если нужного метода нет — получаем AttributeError во время исполнения.
	Производительность списков и коллизий: все эти структуры реализованы как объекты на уровне рантайма. Байткод лишь вызывает их методы и операции; внутренняя реализация (хеш таблицы, over allocation) живёт в C коде интерпретатора.

17. Как выделяется память под объекты в Python.
В CPython (стандартной реализации Python) память под объекты выделяется через иерархический аллокатор pymalloc, заточенный под частые создания и удаления небольших объектов. Плюс есть отдельный путь для больших объектов — через системный malloc.
Иерархия: арена → пул → блок
Это базовая структура pymalloc:
	Арена (arena) — большой непрерывный кусок памяти (обычно 256 КБ). Это единица, которую аллокатор запрашивает у ОС.
	Пул (pool) — кусок внутри арены (обычно 4 КБ, одна страница виртуальной памяти). В одной арене может быть до 64 пулов.
	Блок (block) — минимальная единица выделения под один объект. В пределах одного пула все блоки имеют одинаковый размер (из фиксированного набора размеров, кратных 8 байтам, до 512 байт).
Как это работает на практике:
	При первом запросе на маленький объект аллокатор берёт целую арену у ОС.
	Из арены нарезает пулы под нужные размеры блоков.
	Внутри пула ведёт список свободных блоков (freeblock). Выделение — это просто взять первый свободный блок из списка (O(1)).
	Освобождение — пометить блок как свободный и добавить в список.
Такой подход сильно ускоряет частые аллокации/деаллокации и снижает фрагментацию за счёт группировки объектов по размерам.

Маленькие vs большие объекты
	До ~512 байт (точный порог зависит от сборки) — использует pymalloc (арены/пулы/блоки). Сюда попадает большинство обычных объектов: маленькие списки, словари, кортежи, строки, экземпляры классов и т. п.
	Больше порога — память запрашивается напрямую у системного аллокатора (malloc/free). Для таких объектов нет пулов и классов размеров: каждый запрос обрабатывается отдельно.

Что хранится в объекте: заголовок PyObject
Любой объект в CPython начинается с заголовка PyObject:
c
typedef struct _object {
    Py_ssize_t ob_refcnt;   // счётчик ссылок
    struct _typeobject *ob_type;  // указатель на тип
} PyObject;
Для изменяемых контейнеров (например, списков) сразу после заголовка идёт дополнительная информация (текущий размер, выделенная ёмкость и т. д.).
Таким образом, минимальный размер объекта — это размер заголовка плюс данные самого объекта. Плюс аллокатор может выделять блок чуть больше запрошенного (из за классов размеров), чтобы упростить управление.

Управление временем жизни: счётчик ссылок + сборщик мусора
Счётчик ссылок (ob_refcnt)
	Каждый раз, когда появляется новая ссылка на объект (присваивание, добавление в коллекцию, передача в функцию), счётчик увеличивается.
	Когда ссылка исчезает (перезапись переменной, удаление из списка, выход из области видимости), счётчик уменьшается.
	Если счётчик становится 0, объект уничтожается, а его блок помечается как свободный.
Это даёт детерминированное освобождение памяти для большинства случаев. Проверить текущее значение можно через sys.getrefcount(obj) (учтите, что сам вызов временно добавляет одну ссылку).
Сборщик мусора (циклические ссылки)
Счётчик ссылок не видит циклы вида A → B → A. Для них работает циклический сборщик мусора (gc):
	Он периодически сканирует объекты, отслеживаемые GC (в основном контейнеры, способные хранить циклы: списки, словари, пользовательские классы).
	Находит недостижимые циклы и разрывает их, вызывая деструкторы (__del__) и освобождая память.
Модуль gc позволяет управлять этим поведением (включать/выключать, менять пороги, принудительно запускать сборку).

Важные нюансы про «возврат» памяти ОС
	Освобождённые блоки не возвращаются сразу операционной системе. Они остаются в пулах и аренах для повторного использования.
	Арена освобождается только тогда, когда все её пулы становятся пустыми.
	Из за этого процесс Python может продолжать занимать много памяти даже после удаления большого количества объектов — это нормально и нужно для производительности.
Поэтому в долгоживущих сервисах иногда наблюдают «высокое» потребление памяти, хотя активных объектов уже мало: аллокатор просто держит арены на случай новых запросов.

Особенности для разных типов объектов
	Неизменяемые маленькие объекты (например, маленькие int, некоторые строки) могут кэшироваться или переиспользоваться. Для маленьких целых чисел (−5…256) CPython заранее создаёт и хранит постоянные экземпляры.
	Списки хранят массив указателей на объекты. При росте списка аллокатор выделяет новый массив указателей (это тоже маленький объект), копирует туда старые указатели и освобождает старый массив. Сами объекты при этом не копируются.
	Словари используют хеш таблицу; аллокация идёт под внутренние структуры словаря (массивы индексов и записей).
	Экземпляры классов обычно состоят из заголовка объекта, указателя на __dict__ (если он есть) и слотов (если используются __slots__). __slots__ заметно экономит память, потому что убирает динамический __dict__.

Как посмотреть и поэкспериментировать
python
ПереноситьСвернутьКопировать
import sys
import gc
a = [1, 2, 3]
print(sys.getsizeof(a))          # размер самого списка (массив указателей + заголовок)
print(sys.getrefcount(a))        # счётчик ссылок (на 1 больше из за передачи в getrefcount)

gc.collect()                    # принудительно запустить сборщик мусора
Помните: sys.getsizeof возвращает размер только самого объекта, но не включает память под объекты, на которые он ссылается (например, элементы списка).
Практические следствия
	Частые создания и удаления маленьких объектов — быстро, благодаря pymalloc.
	Циклы ссылок не освобождаются по счётчику, нужен сборщик мусора.
	Память может не возвращаться ОС сразу: это не всегда утечка, а особенность аллокатора.
	Для экономии памяти в больших структурах можно использовать __slots__, массивы (array, numpy), избегать лишних вложенных словарей/списков, где это уместно.

18. Современные best practices: аннотации типов, PEP8, docstring, тестирование (pytest, doctest).
Эти практики действительно сильно повышают качество кода в Python. Я подобрала главные моменты по каждому пункту — так проще внедрять их в работу. digitalogy.co +1
Аннотации типов (Type Annotations)
Это добавление явных указаний на ожидаемые типы переменных, параметров функций и возвращаемых значений. Появились в Python 3.5 (PEP 484). codilime.com +1
Что делать:
	Аннотируйте сигнатуры функций: def add(x: int, y: int) -> int: return x + y.
	Для сложных типов (списки, словари, пользовательские классы) используйте модуль typing: from typing import List, Dict.
	Совет: не перегружайте аннотами простые, очевидные вещи — баланс важен.
	Ключевой шаг: подключите статический анализатор (например, mypy). Он проверит код на несоответствия типов ещё до запуска. Сами по себе аннотации не enforce правила на этапе выполнения — они служат контрактом для инструментов и коллег. digitalogy.co +2
PEP 8
Это официальное руководство по стилю кода Python. Его цель — сделать код читаемым и последовательным. digitalogy.co +1
Основные правила:
	Отступы: 4 пробела на уровень, табуляции не используйте.
	Длина строки: не более 79 символов.
	Имена: snake_case для переменных и функций, CamelCase для классов, UPPERCASE для констант.
	Импорты: сначала стандартные библиотеки, потом сторонние, затем локальные модули. Каждый импорт на отдельной строке.
	Пустые строки: разделяйте функции, классы и крупные блоки кода внутри функций.
Лайфхак: чтобы не следить за стилем вручную, используйте автоматические форматтеры вроде black — они приведут код в соответствие с PEP 8 одним кликом.
Docstring
Это строковый литерал (в тройных кавычках), который идёт сразу после определения модуля, функции, класса или метода и служит для их документирования. timeweb.com +1
Рекомендации (PEP 257): timeweb.com +2
	Для простых функций подойдёт однострочная докстрока. Для сложных — многострочная: сначала краткая сводка, затем пустая строка, потом детали. zerotomastery.io +1
	В докстроке функции опишите: что она делает, какие аргументы принимает (с типами), что возвращает, какие исключения может выбросить. timeweb.com +1
	Для классов укажите общее назначение, публичные атрибуты и методы.
	Старайтесь писать понятно: объясняйте не только «что», но и «зачем».
	Важное правило: всегда обновляйте докстроку, если меняете код.
	Можно использовать распространённые форматы (Google, NumPy/SciPy) — главное, быть последовательным в проекте.
	Из докстрок можно генерировать внешнюю документацию (например, с помощью Sphinx). devacetech.com +1

doctest
Этот инструмент позволяет встраивать примеры использования прямо в докстроки. geeksforgeeks.org +1
Как это работает:
	В докстроке пишите примеры в формате интерактивных сессий Python (строки, начинающиеся с >>>).
	В конце файла добавьте блок:
python
if __name__ == "__main__":
    import doctest
    doctest.testmod()
	При запуске скрипта doctest проверит, совпадают ли реальные результаты с теми, что указаны в примерах.
Плюс: такой подход решает сразу две задачи — документирует код и служит простым юнит-тестом.
Несколько общих советов
	Не пытайтесь внедрить всё сразу. Начните с малого: например, добавьте аннотации в ключевые функции проекта или запустите mypy.
	Обсуждайте стандарты в команде. Единообразие в проекте важнее следования каким-то правилам в одиночку.
	Регулярно рефакторите тесты. По мере развития кода тесты тоже нужно обновлять, чтобы они оставались актуальными и полезными.

Задачи к уроки:
Задание 1: Работа с базовыми типами данных.
Напишите программу, которая демонстрирует разницу между изменяемыми и неизменяемыми типами данных в Python.
1. Создайте список и кортеж
2. Попробуйте изменить их элементы
3. Объясните, почему одни операции работают, а другие нет

Задание 2: Работа со списками.
Создайте программу, которая:
1. Создает список из 10 чисел
2. Находит максимальное и минимальное значение
3. Сортирует список двумя разными способами
4. Измеряет время выполнения каждой операции сортировки

Задание 3: Словари и множества
Напишите программу, которая:
1. Создает словарь с информацией о студентах (имя, возраст, оценки)
2. Находит всех студентов с оценкой выше 4
3. Создает множество уникальных оценок
4. Демонстрирует разницу между списком и множеством при поиске элементов

Задание 4: Линейный и бинарный поиск
Реализуйте:
1. Функцию линейного поиска
2. Функцию бинарного поиска
3. Сравните их производительность на отсортированном списке из 1000 элементов
4. Объясните, почему бинарный поиск работает быстрее

Задание 5: Сортировка
Реализуйте:
1. Пузырьковую сортировку
2. Сортировку вставками
3. Сравните их с встроенной функцией sorted()
4. Измерьте время выполнения для разных размеров входных данных

Задание 6: Работа с памятью
Напишите программу, которая:
1. Создает список и кортеж одинакового размера
2. Измеряет объем памяти, занимаемый каждым
3. Демонстрирует, как изменяется размер списка при добавлении элементов

Задание 7: Хэширование
Создайте программу, которая:
1. Демонстрирует работу хэш-функции для разных типов данных
2. Показывает, почему некоторые типы данных нельзя использовать как ключи словаря
3. Объясняет, что такое коллизии и как они обрабатываются

Задание 8: Связанные списки
Реализуйте:
1. Простой односвязный список
2. Методы добавления и удаления элементов

4. Сравните производительность с обычным списком Python

Задание 9: Деревья
Создайте:
1. Бинарное дерево поиска
